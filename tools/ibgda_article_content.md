## 三、IBGDA DEMO：国产 GPU 与 RDMA 网卡的深度协同

### 3.1 技术背景：为什么 MoE 需要 IBGDA？

在 **MoE（Mixture of Experts）** 模型典型训练或推理中，**专家并行（Expert Parallelism）**通信包含两个核心阶段：

- **Dispatch（分发）**：把 token 路由到对应专家
- **Combine（聚合）**：把专家输出汇总回原 token

这两个阶段涉及**海量小粒度数据交换**——这是 AI 集群通信的"老大难"。

在传统跨节点通信中，GPU 必须经由 CPU 中转指令，产生**额外延迟**与 **CPU 开销**。而 **IBGDA（InfiniBand GPU Direct Async）** 技术正是为解决这个问题而生：通过**绕过 CPU 处理环节**，显著降低指令中转等待时间，在 **All-to-All 通信**场景中实现**吞吐提升**与**延迟压降**。

### 3.2 国际对标与国产缺口

| 阵营 | 现状 |
|------|------|
| 🟢 英伟达 | 凭借 **GPU + ConnectX 系列网卡** 深度协同，率先实现 IBGDA 方案 |
| 🟡 国产 GPU | 需支持类 NVSHMEM 编程、最新 NCCL 通信库、DeepEP 等集合通信库 |
| 🟡 国产 RDMA 网卡 | 与国产 GPU 在软硬件层面完成适配，方能实现 GPU 直通网卡高效通信 |
| 🔴 规模化落地 | 国产 GPU 直通国产 RDMA 网卡的**规模化落地案例仍相对罕见** |

奇异摩尔的 IBGDA Demo 正是为了填补这块空白。

### 3.3 奇异摩尔 IBGDA 方案规格

**产品规格一览：**

- ✅ **单通道 400G RDMA ASIC 引擎**
- ✅ 基于 **Kiwi SNIC 800G** 平台架构设计
- ✅ 完成**软硬件协同开发**
- ✅ 兼容专为 MoE 模型优化的**集合通信库**（对标 DeepEP）
- ✅ **原生支持 IBGDA**（GPU 直接发起通信）机制

![Kiwi SNIC 800G 平台架构](https://zhoujungis.github.io/photos/kiwi-snic-arch.svg)

> 上图为 **Kiwi SNIC 800G** 平台架构：左端为搭载类 NVSHMEM / DeepEP 通信库的国产 GPU，中间是单通道 400G RDMA ASIC 引擎（含 PCIe Gen5 主机接口、IBGDA 核心、可靠传输 / QP 调度、400G MAC + 112G SerDes），右端为开放以太网侧的国产 ToR / Spine 交换机。整套方案基于**开放以太网**生态构建，为国产算力集群提供兼具高性能与自主性的 Scale-Out 网络选择。

### 3.4 核心测试结果

该 IBGDA Demo 测试平台对标英伟达 IBGDA 测试数据，实测结果达到相应水平：

![IBGDA vs 传统 IBRC 性能对比](https://zhoujungis.github.io/photos/ibgda-perf-chart.svg)

> 上图为 **IBGDA vs 传统 IBRC** 方案在 All-to-All 场景下的实测对比：左半部分为四组吞吐量对比（单次小消息带宽、原始小包吞吐、合并发送吞吐、All-to-All 带宽），蓝色为 IBGDA 直通方案，灰色为传统 IBRC 方案；下方为延迟对比（18 μs → 10 μs，缩短约 44%）；右半部分为核心指标提升小结。

| 指标 | 提升效果 |
|------|---------|
| 单次小消息带宽 | **显著跃升**（15 → 52 GB/s，提升约 247%） |
| 原始小包吞吐量 | **实现质的跨越**（22 → 75 GB/s，提升约 240%） |
| 合并发送吞吐量 | **实现质的跨越**（28 → 82 GB/s，提升约 193%） |
| **All-to-All 通信延迟** | **大幅缩短，接近翻倍提升**（18 → 10 μs，压降 44%） |
| 小包惩罚 | **被彻底消除** |

> 💡 **关键洞察**：延迟压降 44%、吞吐量翻倍，最直接的收益是 MoE 训练 / 推理的"专家通信墙"被打破；同时 CPU 算力被释放回前台任务，**整体集群吞吐**与**单节点算力利用率**同时得到改善。

### 5.1 行业洞察：三条指数曲线同时驱动

大模型算力需求被**三条指数曲线**同时驱动：

1. **训练侧的 Scaling Law** —— 模型规模与数据规模的同步扩张
2. **推理侧的 Test-time Scaling** —— 推理时计算量的指数增长
3. **Agent 应用带来的调用量爆发** —— Agent 范式推动推理调用频次陡升

> 因此，真正决定格局的越来越落在**互联、整机、软件和系统协同**上。
