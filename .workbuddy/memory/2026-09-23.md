### 技术要点
- **三种返回值含义**：`null`（子树里一个都没有）/ `p` 或 `q` 本身（**只是信使，不是答案**）
  / LCA 自己（答案，继续往上冒）。
- **「一个节点也可以是它自己的祖先」自动处理**：靠 `if not root or root is p or root is q: return root`
  这一行「命中即返回，不再下探子树」。**不需要为「p 是 q 的祖先」单独写分支。**
- **分叉点判据**：`if left and right: return root` —— 左右都非空的那个节点是 LCA，**全树唯一**。
- **显式栈模拟递归**：栈帧 `{ id, stage, from }`，stage 有 `enter / left / right / decide`。
- **`deliver` 必须在 `stack.pop()` 之前调用**（初版踩坑：返回到爷爷身上而非父节点，
  主例只出 8 帧、子树完全没展开）。`frame.from`（'L'|'R'|null）标明是父节点的哪一侧孩子。
- 演示默认例用 **p=6, q=4**（不是官方第一例 p=5,q=1）—— 官方例只有 8 帧，看不出后序回溯。
- **`answer` 的裁定要收尾统一做**：分叉点情形在 decide 阶段就能写 answer；但**祖先情形命中时
  根本走不到 decide**（命中即返回），只能靠「根最终冒出来的返回值」来定。
  单测就是这么抓出 bug 的（13 例挂掉，全是祖先场景 answer=null）。
- **`alreadyAnswer` 标注**：`ret === answer` 时把 `returnSource` 标成 `'lca'`，
  否则答案在往上冒的路上会被误标成 `'p'`/`'q'`。

### 修复的坑
- **单测口径**：不变量用例必须给「树里真实存在的 p/q」—— 默认 6/4 在小树上不存在，
  `pId`/`qId` 是 `undefined`，递归一个都命中不了（是测试构造问题，不是状态机问题）。
- **「左右都非空只出现一次」的判据要收敛**：不能只看 `phase==='decide' && returnSource==='lca'`

- **返回值标签布局**：初版挂左上角，会和「左孩子的标签」叠（父在左上、子在左下，都往左上飘）。
  改成**贴节点正上方居中**，落在两层之间的空当里。
- **栈行宽度**：`STACK_ROW_W` 152 → 214（`depth N · dfs(x) · 刚进入` 会溢出裁字），
  `STACK_ROW_GAP` 5 → 10（相邻行贴太近）。
- **`paint(_index, step)` 签名**：`onRender(index, steps[index])` 第一参是 index 不是 step。
- **收尾照抄 `levelOrder.js`**：`player.jumpTo(Math.trunc(options.initialStep) || 0)` +

### 技术要点（本题的两个真难点）
- **① 返回值（gain）和答案（through）是两个不同的量，必须分开算。**
  - `gain = val + max(左, 右)` —— **一条胳膊**（直链），交给父节点继续往上传；
  - `through = val + 左 + 右` —— **两条胳膊**（拱形），以本节点为拱顶，**到此为止**，只用来更新 `best`。
  - **为什么 gain 只能选一条胳膊**：路径不能拐两次弯。父节点拿到 gain 后会**再拐一次**；
    若这里两条胳膊都用掉，父节点再拐就变成"树杈"，不是路径（节点会重复出现）。
  - 一句话记法：**返回一条边，答案一个尖。**
  - 演示证据：官方例第 9 帧 `20` 的 `through = 42` / `gain = 35`，差的 7 就是没带走的右胳膊。
- **② `max(gain(child), 0)` 里的 0 就是本题的优化本身**，不是防御性编程。
  负胳膊接进来只会让和更小 → 返回 0 表示"别走我这边"。反例 `[1,-5,3]`：不剪是 -1，剪了才是 4。
- **`best` 必须初始化 `-Infinity` 不能是 0**：题目保证"路径至少含一个节点"，`[-3]` 用 0 会错答 0。
- **「路径不一定经过根节点」**：官方例根是 `-10`，最优路径 `15 → 20 → 7` 根本不经过根；
  根的 `through = -10 + 9 + 35 = 34 < 42`。

### 修复的坑（都是硬 bug，值得记）
- **`bestPath` 重建不能只沿 `parent` 往上走**（初版主线 bug）：拱顶路径的两条胳膊
  **都是往下的**。初版写成 `pathFromNode` 只沿 parent 上行，42 那条路被错写成
  `20 → -10`（走去了根）。正确做法 `buildArchPath(apex)`：从拱顶出发，往左右各找
  "贡献更大的那条下行链"（只在孩子 `rawOf > 0` 时才走），拼成
  `左链(reverse) + 拱顶 + 右链`。
- **`gainOf` / `rawOf` 的键是节点 id，不是节点值**：单测里写成 `gainOf[nodes[id].value]`
  会拿到 `undefined`（-10/9 这些值当键很危险）。踩了 3 例。
- **`pruned` 只记录了左孩子**：原来的 `pruned.push` 写在 `left` stage 分支里，
  右孩子的负贡献永远进不了 `pruned`。改成在 `decide`（唯一判定点）里左右都记。
- **渲染层三个视觉 bug**（截图看出来的）：
  1. `gain` 标签被父边压住 → `LEVEL_GAP` 84→96，标签上移到 `-NODE_R-33`；
  2. `is-apex` 同时表示"在路径上"和"是拱顶"，导致终帧 15/20/7 全戴金圈、
     真正的拱顶 20 淹没 → **拆成 `is-onpath`（细圈）+ `is-apex`（粗圈 + 外环）**；
  3. **按 id 顺序 append 节点导致后画的圆圈盖住先画节点的标签** →
     **分层绘制：edges → nodes → labels**，标签统一画在最上层；
     同层相邻节点距离不够时，`labelShift` 把标签往各自外侧借位（避免 `gain 15`/`gain 7` 相撞）。
- **`**` 裸残留被 guard 抓住**：正文里写 `sys.setrecursionlimit(10**6)`，
  markdown 的 inline code 不会转义 `**`，于是 HTML 里留下裸 `**`，
  被 publish 脚本的 "unbalanced bold" guard 拦下。改成 `sys.setrecursionlimit(1000000)`。
  **教训：代码片段里别出现 `**`（Python 幂运算符），会污染 markdown 渲染。**

### 变体关系（写进文章第六/七节）
**124 / 543 / 687 三题共用同一个 10 行骨架**，只换"两个量"的定义：
| | 124 | 543 | 687 |
|---|---|---|---|
| 返回值（一条胳膊） | `val + max(左,右)` | `1 + max(左,右)` | `max(左有效,右有效)` |
| 答案（两条胳膊） | `val + 左 + 右` | `左 + 右` | `左 + 右` |
| clamp | **需要** | 不需要（深度非负） | 用"值相等"条件归零 |
| `best` 初值 | `-inf` | `0` | `0` |
- 543 不需要 clamp，恰好反证 124 的 `0` 是**为"值可为负"这个前提服务的**，不是通用写法。
- 1123 最深叶 LCA 同构：`if ld == rd: 自己是拱顶 / else: 带走更深的那条`。
- 乘法变体**不能盲目 clamp**（负负得正），要同时维护最大/最小两个返回值。
