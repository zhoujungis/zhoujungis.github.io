### 文章立意
1. **四种解法是同一个问题的四种回答** —— 核心公式
   `water[i] = max(0, min(左最高, 右最高) - height[i])`，全部区别只在"怎么拿到这两个数"。
2. **双指针的正确性论证**（面试分水岭）：矮的一端的外侧上界已由对面的柱子保证；
   反证：若左侧高柱真是短板之外的那边，它当年经过时判据就不会选它，右侧会被一路收缩
   到出现更高的柱子为止。完整论证写在文章第六节。
3. **单调栈 = 横着切**：同一格的水会被分几次到账 —— 官方例下标 5 的 2 单位水
   是 `i=6` 加 1 层、`i=7` 再加 1 层。两个动画对此给出了最直观的对照
   （双指针一次画完 2 格水；单调栈画成上下两层）。
4. **三维版（LC 407）的推广**：一维的 `min(左最高, 右最高)` 其实就是
   "往左走"和"往右走"两条路径的瓶颈取 min；二维把"两条路径"换成"所有路径" ——
   **最小瓶颈路径 = 多源 Dijkstra**（最小堆 + BFS，从边界向内灌）。
   一维是二维的退化特例，这一对题放一起木桶原理才贯通。

### 校验结果
- **24 组输入**：双指针、单调栈、暴力参考解**三向交叉**，总水量与**逐格水量**都一致
- 不变量：双指针（l 只增 r 只减、LM/RM 单调不减、total 单调不减、
  结算侧别与判据一致、gained = 新 max - 高度）；单调栈（栈内高度递减、
  每个下标恰好按序入栈一次、settle 四公式 width/layerH/level/gained、
  **逐格增量之和 = gained**）
- 专门一条测试钉死"下标 5 分两次加水"（直接断言 water[5] 的两次变化 `0→1→2`）

## LC 53 最大子数组和 —— 算法系列第十八篇，端到端发布完成

用户给的题（腾讯 TOP4，追问：返回子数组本身 / 环形版 918 / 分治）。

### 产出
- `article/lc-53-maximum-subarray.md`（12 节，18 分钟阅读，约 11000 字符）
- `frontend/src/viz/kadaneSteps.js` + `kadane.js`（Kadane 状态机，**10 帧**）
- `frontend/src/viz/__tests__/kadaneSteps.test.js`（**22 例**，一次全绿）
- `tools/make_lc53_cover.py` / `tools/publish_lc53_article.py`

- 标签新增「动态规划」(slug `dp`)
- 全量单测 **730 → 752** 通过

### 文章立意
1. **Kadane 只有一句话**：`cur = max(x, cur + x)` —— 整句只在问
   "带上前面那段，是赚了还是亏了？"。`cur < 0` = 前面是负资产 = 扔掉重起。
2. **值视角 vs 位置视角**：`max(x, cur+x)` 和 `if cur < 0: 重置` 是同一件事的两种写法；
   写返回值用前者，**返回子数组本身必须用后者**（位置只存在于后者）。
3. **为什么扔掉整段不漏解**：前面为负时，任何包含它的候选都比不包含的差，
   所以"以 i 结尾"的最优一定不含负段；更早的最优已记在 best 里。两头都照顾到了。
4. **分治四元组**（l_sum/r_sum/i_sum/m_sum）+ 合并公式 —— 并**纠正一个流传很广的错误**：
   带缓存的分治合并 O(1) × 2n-1 节点 = **O(n)**，不是网上普遍写的 O(n log n)
   （那是朴素分治每层重扫区间的账）。它的价值是能升级成线段树。
5. **LC 918 环形版**：绕圈 = 总和 − 最小子数组和（同一个算法反着用）；
   **全负数时 total − minSum = 0 对应空子数组，必须特判**（`maxSum < 0` 或 `minSum == total`）。
6. **LC 121 股票 = 差价数组的 Kadane** —— 变体节里最值得记住的联系。

### 校验结果
- **18 组输入与两个独立参考解三向交叉**（暴力枚举 + 前缀和最小值版），全一致
- 主例 10 帧：答案 6，区间 [3..6] = [4,-1,2,1]，与暴力参考解**区间完全一致**
- 22 个单测一次全绿：cur 与区间实和恒等、best 与最优区间实和恒等、
  子数组非空、best 单调不减、restart/extend 的前置条件（上一帧 cur < 0 / >= 0）、
  restart 帧丢弃的正是上一帧的当前段、improved 帧的刷新关系

### 渲染层的经验：两个视觉通道分离（坑 V 的发展）
LC 53 的格子有四种状态会叠在同一格上（当前段 / 最优 / i 指针 / 被丢弃）。
**解法不是排 CSS 优先级，而是把状态拆到两条互不干扰的视觉通道**：
- **fill**（底色）= 是否在当前子数组里（绿）
- **stroke**（边框）= 最优（金）/ 当前 i（橙）/ 被丢弃（灰虚线）
fill 和 stroke 天然正交，任何状态组合都不会互相覆盖。
**以后遇到"多种状态叠同一元素"，先想能不能拆成 fill/stroke/ring 三条通道，
拆不开才用互斥。**（LC 15 的五状态是互斥排的，LC 53 这招更干净。）

### 动画的灵魂动作：重置
restart 帧新增 `dropped: {from, to}` 字段（被扔掉的那一段），
渲染层把这段画成灰虚线格子。**"扔掉负资产"从一句话变成看得见的动作** ——
两次重置分别扔掉一格（[-2]）和两格（[1,-3]），重置粒度完全由 cur 何时变负决定。

### 文章立意
1. **两条轴**：215 在值轴选位置，347 在频率轴选前缀 —— 排序的键决定一切。
2. **位置即排名**：分区后枢轴落点就是最终排序位置，所以一次分区确定一个元素的排名，
   只进一边 → O(n)。正确性论证 + 几何级数 `n + n/2 + n/4 ≈ 2n`。
3. **索引陷阱**：第 k 大 = 升序下标 n-k（写成 k-1 是第 k 小）；对称数组样例两种理解答案相同 ——
   又一个"官方样例掩盖 bug"的实例（系列第四次）。
4. **347 的语义陷阱（反向）**：官方例 2 `[3,2,3,1,2,4,5,5,6]` k=4 → 4 钉死
   "第 k 大是排序后第 k 个位置，不是第 k 个不同值"（按不同值算是 3）。
   与 215 的"各占各的位置"恰好互为镜像，合并篇的对照价值就在这。
5. **两个最坏情况（实测）**：升序数组 + pivot=last + k=n：n=6 要 5 轮（随机 2 轮）、
   n=8 要 7 轮（随机 2 轮）；**全相同元素 + Lomuto 即使比较写 <= 依然每轮只砍 1 个**（[5]x6 k=n 要 5 轮）
   —— 三路分区（荷兰国旗）存在的理由。introselect/nth_element 也写了。
6. **堆 vs 快速选择四维对照**：时间/空间之外的两个关键维度 —— **能否流式**（堆能、快选不能）
   与**改不改原数组**（快选改、堆不改）。海量数据（10 亿找前 100 大）的选型全由这两个维度推出：
   流式堆 → 去重也装不下就哈希分桶分治 → 值域小用计数。

### 校验结果
- **快速选择**：16 组输入与排序/小根堆两个参考解三向交叉 + 随机 pivot 策略全对 +
  逐帧不变量（target=n-k、分区有序性、区间单调收缩且目标位不逃逸、数组是排列、不修改输入）+
