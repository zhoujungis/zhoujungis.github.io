## Agent 工程 06（agent-security-run-commands-safely）

## Agent 工程 09（agent-token-economics）

- 选题定位：系列第八篇讲「账本」，这篇讲「有了账本之后怎么花钱」。标题《Token 经济学：同一任务十倍的差价》，slug `agent-token-economics`。

- 成本模型：`cost ≈ Σ_t [ P_in × (S + H_t) + P_out × O_t ]`；`total_in ≈ N × S + d × N(N−1)/2`。40 轮算例（S=3,000、d=1,200）：无缓存 1,056,000；中途压缩一次 576,000；全程前缀命中 51,000（约 20 倍）。缓存价按 1/10 估算时，第三行等效约 48,300 个全价 token，与第一行差约 22 倍。
- 七个成本缺陷（全部回源码取证）：`CONTEXT_CHAR_BUDGET = 120_000` 比较的是 `m.to_string().len()`（UTF-8 字节）；`MAX_PROJECT_DOCS = 20_000` 同样用 `joined.len()`；`clamp(s, max_output)` 用 `s.len()` 且提示文案写 `chars omitted`（中文偏大三倍）；`web_fetch` 的 `max_chars`（字符，默认 20,000、上限 200,000）被 `dispatch` 的 20,000 字节覆盖，形成四层单位不同的漏斗；`image_part` 无字节上限、base64 放大 4/3，`MAX_ATTACHED_IMAGES = 4` 只管张数（四张 5 MB ≈ 27 MB，超过多数网关 10 MB）；`set_memory_block` 每轮把重检索的记忆块写进 `messages[0]`，`set_block` 删旧块后追加到末尾 → 从记忆块起的历史全部失效；`compact_with` 的触发只看 120,000 字节与 `KEEP_RECENT + 1`，不看「还剩多少轮」，短任务压缩纯亏。

## 经验（Agent 工程 09）

- 写「参数/能力」类缺陷前，先看参数是否**已经存在**：`read_file` 的 `offset` / `limit` 一直都有，真正的问题是默认值、单位与截断提示的配合。把「缺参数」当成结论，比漏讲更伤可信度——读者一试就发现参数早就在。
- 算例表的三行必须各自口径单一：初稿把「无缓存」「中途压缩」「前缀命中」混成一张表，第三行数字是 51,000 却解释成「两段 190 的三角和」，二者不可兼容。改成「无缓存 / 无缓存 + 压缩一次 / 全程前缀命中」三行、并把压缩的收益明确限定在二次项后，才自洽。
- 封面里的数学符号（Σ / ≈ / × / − / ²）一律交给中文字体，代码字体只放纯 ASCII 标识；分隔符 `" · "` 的 `·` 也是非 ASCII，`assert_ascii()` 会当场拦下——这次正是它拦下的。
- 「同一任务十倍差价」的叙事支点不是单价，而是「重复内容有没有命中缓存」：先把 `S / H_t / O_t` 三个量拆开，读者才知道该改哪一段；只讲「用便宜的模型」是最没用的建议。
- 成本类文章的收尾要落在可验证的实验上（固定 system、默认分页按字节预算、`max_tokens` 调大看失败率），三个实验都只需要请求体字节数与轮数，本地可取，不依赖服务商后台。
