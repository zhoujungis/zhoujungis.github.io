| | LC 104 最大深度 | LC 226 翻转二叉树 |

| 递归里做的事 | 先问子树高度，再算自己 | 换掉自己的两个孩子 |

### 两颗钉子（文章的核心卖点）
- **104 的钉子长在 111 上**：`1 + min(左, 右)` 是**错的**。
  **空子树不是叶子** —— `[1,2]` 错答 1（正确 2）、`[1,2,null,3]` 错答 1（正确 3）。
  `max` 侥幸掩盖了这个坑（`max(1,0)=1` 恰好淘汰 0），`min` 一下露馅。
  正确写法要把单侧空的两个分支先摘出来。
- **226 的钉子长在「交换的位置」上**：顺序确实无所谓，**唯独不能把交换夹在两个递归中间** ——
  因为交换改了 `root.left` 的指向，第二行递归进的是"从没翻过的那棵"，而翻好的那棵被翻第二次。
  交换要么放最前、要么放最后。

### LC 226 的核心洞察（决定了渲染层实现）
**翻转二叉树 ≡ 把每个节点从根到它的路径逐位取反（L↔R）。**
状态机因此不存"节点该画在哪"，只存每个节点的**相对左右角色** `sideOf`；
位置 = 沿 parent 链拼出路径 → 满二叉树槽位法算列号。交换一次 = 改一个 role，
节点 x 坐标自然跳到镜子里 —— **这就是"看到树在翻"的来源**。
推论：**翻转是自逆运算**（逐位取反两次 = 原值）。

### 修复的坑（都是硬 bug）
- **⚠️ 226 状态机跳过 stage（主线 bug）**：交换后如果"交换得到的左孩子"是 null，
  初版直接把 `stage` 跳到 `'right'` —— 于是 `left` 阶段被整个跳过，
  而**原来那个左孩子正等着在 left 阶段被递归**（交换后它是右孩子）。
  症状：`[1,2,null,3]` 只交换了根，整条左链一个节点都没访问（交换数 1/2）。
  **修法：永远 `stage = 'left'`，让 left 阶段去决定要不要 push。已加回归测试。**
- **⚠️ 渲染层 `posWith` 权重写反**：从**子往父**走时，最深那一位是**最低位**，
  必须递增权重累加（`col += weight; weight *= 2`）。初版写 `col = col * 2 + bit`，
  等于把最深那一位当最高位，节点左右错位（节点 6 期望列号 0b10=2 被算成 0b01=1）。
  **纯逻辑测试测不出这个错**（trace 只用 sideOf 推路径），**只有渲染层截图能暴露** ——
  所以写完渲染层必须出图看一眼。
- **测试里又用「节点值」当键（重复踩 skill 坑 H）**：`[0,0,0]` 三个节点值全是 0，
  `out[n.value] = path` 只剩 1 个键。**改用节点 id 做键**。LC 124 踩过一次，这次又踩。
- **测试用例用了非法层序编码**：`[1, null, 2, 3]` 里下标 3 的父是下标 1（null）→
  `buildTree` 建出一个 `parent === -1` 的**孤儿节点**，参考解从根走根本到不了它。
  层序编码的合法约束是「下标 i 的孩子必须在 2i+1 / 2i+2」。改用 `[1, 2, 3, null, 4]`。
- **`**` 裸残留又被 guard 抓住（skill 坑 M 的变体）**：Max Howell 引文里写
  `f\*\*\* off`，markdown 把 `\*` 转义成 `*`，三个连着就成了裸 `***` → 触发守卫。
  改成「so …（原话结尾是一个脏字。）」。
  **规则扩展：不只是代码片段，引用块里的转义星号同样危险。**
- **封面叶子层节点相切**：`STEP_R = 27` 但节点半径 14（直径 28 > 27）→ 最下层四个节点挤成一团。
  **约束：叶子层相邻间距必须 > 节点直径。** 改成 `STEP_R = 32 / R_NODE_R = 12`。
- **封面根节点的 `h=3` 标签撞左区标题**：标签框占 `[cy-48, cy-28]`，标题在 y=186 时正好重叠。
  树整体下移 + 标题上移解决。
- **`done` 帧不该高亮 `current`**：226 收尾帧把根描成橙色粗圈，和"全部翻完"的语气不符。
  加 `step.phase !== 'done'` 判断。

### 渲染层的两个通用改进（值得沉淀）
- **动态 `LEAF_STEP`**：浅树写死步长会让树挤在画布中间一小块。
  按层数反推：`Math.min(120, Math.max(58, Math.round(470 / 2 ** maxDepth)))`，
  让树宽恒在 470 左右。104（3 层）和 226（3 层）都受益。
- **分层绘制照旧**（edges → nodes → labels，坑 K），104 的 `h=` 标签同样需要 `labelShift`。
