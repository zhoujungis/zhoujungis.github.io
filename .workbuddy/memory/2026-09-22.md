## LC 82 文章发布（第九篇算法文）
- article/lc-82-remove-duplicates-from-sorted-list-ii.md（18 min 阅读）：主线是「为什么头节点这里必须有个 dummy」——82 要「重复的一个都不留」，重复段第一个节点也要删，而它的前驱可能是原 head；架 dummy 后「没有一个节点是特殊的」，返回必须 `dummy.next`（head 可能已成孤儿）。核心易错点是 prev 推进规则：只在 else 分支（确认 curr 不属于重复段）才 `prev = curr`，发现重复时 prev 必须冻结在重复段前面当「接回点」，最后 `prev.next = curr` 一次摘掉整段
- 对照点：LC 83 vs 82（`prev.next = curr.next` 删当前 vs 整段跳到段外再 `prev.next = curr`）；判据跟着题目走（LC 160 比引用、LC 82 比值）；内层 while 不算嵌套（内外推同一个 curr，摊还 O(n)）
- 阿里变体（用户确认语义为「重复过的值留一个，没重复过的照留」）：`1→1→1→2→3→3→4 → 1→2→3→4`，改法只有一处 —— 接回时接 `last`（重复段最后一个节点）而非 `curr`，并 `prev = last`。注意：用户原话给的 `1→3` 是笔误，已通过 AskUserQuestion 澄清
- 动画：removeDupSteps.js（状态机，mode: 'remove-all'|'keep-one'，29 单测）+ removeDups2.js（SVG 渲染：slot0 留给 dummy，curr 徽标在上 / prev 徽标在下体现「错位」，重复段橙色虚线框，摘链帧 prev→curr 橙色弧线 `prev.next = curr`），注册 algo-viz--lc82；全量 262 测试过
