## LC 160 文章发布（第八篇算法文）
- article/lc-160-intersection-of-two-linked-lists.md（17 min 阅读）：核心是「双指针交换游标」——pA 走完 A 换到 B 的头、pB 反之，由 a+c+b == b+c+a 推出两路等长必然同点。重点讲清：判据是节点引用不是值；相交必为 Y 字（单 next 不可能 X）；while pA is not pB 靠两个 None 相等自然退出无需特判；换头只改指针变量不动 next，故不破坏结构不造环
- 动画：intersectSteps.js（状态机，21 单测）+ intersectLists.js（Y 字布局：公共段落 A 行、独有段各占一行、跨行 S 形汇入边、HOP_LANE 换头折线），注册 algo-viz--lc160；全量 233 测试过
- 状态机核心坑：游标必须编码为 (on:'A'|'B', i) 二元组，单个"公共下标"表达不了 pA 走到 B 上的情况；初版用单 iA/iB 索引共享 pool 导致换头后位置错、continue 不前进形成交换乒乓死循环
- 渲染踩坑合集：跨行汇入边控制点必须放区间外侧（放内侧会自折叠成垂直短线不可见）；换头弧线别绕整个画布（放弃大回环改走 HOP_LANE 紧凑折线）；chip 要跟随游标所在行动态挪行否则引线横穿全图；∅ 需指定 Segoe UI Symbol 否则渲染成斜杠零；X_OFFSET 声明必须在 colX 之前（否则 TDZ）
- 空路径守卫用 Array.isArray 而非 .length（空链表是合法输入，用 .length 会被默认值顶掉）
- 视觉验证复用 frontend/scripts/viz-shot.mjs（新增，jsdom+ssrLoadModule+sharp 把指定帧转 PNG）
- 封面 make_lc160_cover.py：中英混排必须逐段排版（Consolas 无中文字形会 tofu），写 mixed_text(cx,cy,parts) 按段选字体
