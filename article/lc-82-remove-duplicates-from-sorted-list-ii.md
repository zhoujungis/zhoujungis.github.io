# 【LC 82】删除排序链表中的重复元素 II：为什么头节点这里必须有个 dummy

> **适用读者**：做过 LC 83（保留一个），觉得"删重复"已经会了，然后被这题的一个都别留卡住的人
> **技术栈**：Python 为主，附 Java 版
> **难度**：中等（代码 15 行，但 `prev` 到底什么时候前进，是最容易写错的地方）
> **收获**：dummy 哨兵「到底在解决什么问题」的准确答案，以及 prev / curr 这对指针的推进规则

## 题目

给你一个已排序的链表的头 `head`，**删除原始链表中所有重复数字的节点，只留下不同的数字**。

```
输入：head = [1,2,3,3,4,4,5]
输出：[1,2,5]
解释：3 和 4 都出现过重复，所以它们一个都不留

输入：head = [1,1,1,2,3]
输出：[2,3]
解释：1 出现了三次，全删；2、3 各只出现一次，保留
```

注意加粗那句：**出现过重复的值，一个都不留**。这跟 LC 83 是两回事 —— 83 是"每个值留一个"，结果会是 `[1,2,3,3,4,4,5] → [1,2,3,4,5]`。82 要的是 `[1,2,5]`。

> 出处备注：暑期实习面经里高频出现。这题被选中的原因往往是它和 LC 83 只差一行条件，用来快速分辨"真理解指针"还是"记得模板"。

链表节点的定义，沿用前几篇：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

---

## 一、先想清楚：为什么这题比 LC 83 难

### 1.1 排序这个条件给了什么

链表已经排好序，所以**重复的元素一定挨在一起**。不需要哈希表去统计每个值出现几次，只要顺着走，看到"当前节点和下一个节点值相同"就知道碰上重复了。

这是这题唯一一个"送分"的地方：**判重不用回看，只看邻位**，`O(1)` 空间是白送的。

### 1.2 真正的难点：删除需要前驱

删除一个节点 `x`，在单链表里只有一种做法：

```python
x 的前驱.next = x.next
```

也就是说，**要删一个节点，你必须先拿到它的前驱**。

现在问题来了：LC 83 里，重复时保留第一个、删后面几个 —— 被删的节点总是有前驱的（前驱就是保留下来的那个）。所以 LC 83 里 `prev` 永远安全。

但 82 要"一个都不留"：重复段里的**第一个节点也要删**。而那一段的第一个节点，它的前驱可能是……**原来的 head 自己**。

最极端的例子：

```
输入：1 → 1 → 2
输出：2
```

这里 `head` 本身（第一个 `1`）就要被删掉。可 `head` 没有前驱 —— 你没法执行 `head 的前驱.next = head.next`，因为 `head 的前驱` 根本不存在。

### 1.3 dummy 哨兵：给头节点一个人造的"前驱"

解法是**在头节点前面架一个假的节点**：

```
dummy → 1 → 1 → 2
```

现在 `dummy` 就是头节点的前驱了，删第一个 `1` 变成一次普通的删除操作：`dummy.next = 1.next`。**没有一个节点是特殊的**。

```python
dummy = ListNode(0)
dummy.next = head
...
return dummy.next      # 返回 dummy.next，而不是 head
```

两个必须记住的细节：

- **返回 `dummy.next` 而不是 `head`**。因为 `head` 自己可能已经被摘掉了，那时 `head` 指向的是一个已经脱离链表的孤儿节点。`dummy.next` 才永远是正确的答案。
- **`dummy` 的值随便填**。它不参与比较，`0` 只是习惯（有些题解用 `-1`；如果值域可能到 `-1`，用一个足够小的负数更稳）。

> 顺便说一句：LC 19（删除倒数第 N 个）也用了 dummy，但那题的理由是"可能要删头节点"。**同一个技巧，同一个动机** —— 只要你意识到"操作可能落到头节点上"，就该条件反射地架一个 dummy。

## 二、双指针的推进规则（这一步最容易写错）

架好 dummy 之后，需要两个指针：

- `prev`：已经确认安全的节点的尾巴，也就是"最后一个**确定要保留**的节点"；
- `curr`：正在检查的位置。

主循环的骨架长这样：

```python
prev, curr = dummy, head
while curr:
    if curr.next and curr.val == curr.next.val:
        # 发现重复 —— 这里要整段跳掉
        ...
    else:
        prev = curr
        curr = curr.next
```

**关键在 `else` 那一支：只有确认 `curr` 不属于任何重复段时，`prev` 才跟着前进。**

为什么？因为一旦发现重复，`curr` 会被推着往前跑（去跳过整段），而 `prev` 必须**钉在原地** —— 它是那一段的"接回点"。等 `curr` 跑出重复段了，用 `prev.next = curr` 一次把中间那整段摘掉。

如果 `prev` 跟着一起推，中间那几个被摘掉的节点就会出现在 `prev` 和 `curr` 之间，`prev.next = curr` 之后链表里还挂着半截垃圾。

### 2.1 发现重复之后做什么

```python
if curr.next and curr.val == curr.next.val:
    dup_val = curr.val
    while curr and curr.val == dup_val:
        curr = curr.next        # curr 一路冲到重复段之外
    prev.next = curr            # 一次接上，中间整段被摘出
```

注意这里**没有** `prev = prev.next`。`prev` 就是不动。

内层 `while curr and curr.val == dup_val` 里那个 `curr and` 不能省：如果重复段一直延伸到链表末尾（比如 `1 → 2 → 2`），`curr` 会一路跑到 `None`，没有 `curr and` 就会在 `curr.val` 上抛 `AttributeError`。

### 2.2 为什么内层用「值」比较就够了

`curr.val == dup_val` 比的是**值**，不是节点 —— 这和 LC 160 相交链表里"必须比引用"正好相反，值得对照记一下：

| 题 | 判据 | 为什么 |
|---|---|---|
| **LC 160** 相交链表 | 必须比**节点引用** | "共享同一批节点"是引用层面的关系，值相同不算 |
| **LC 82** 删除重复 | 比**值**就够了 | 题目要求删的就是"重复数字"，判据本身就是值 |

判据永远跟着**题目在问什么**走，别背成一条死规则。

### 2.3 完整代码

```python
class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)       # 给头节点造一个前驱
        prev, curr = dummy, head

        while curr:
            # 发现重复：curr 和下一个值相同
            if curr.next and curr.val == curr.next.val:
                dup_val = curr.val
                while curr and curr.val == dup_val:
                    curr = curr.next     # 整段跳过
                prev.next = curr         # 一次摘掉整段；prev 不动
            else:
                prev = curr              # 确认安全，prev 才前进
                curr = curr.next

        return dummy.next                # 不是 head —— head 可能已被摘
```

## 三、动画：看着 prev 停在原地等

下面这个动画把 `1 → 2 → 3 → 3 → 4 → 4 → 5` 的全程拆成 15 帧。留意三件事：

- **最左边那个虚线框是 dummy**：它在内存里并不存在，是解法凭空造出来的前驱。整条链的实际起点是它右边的 `1`；
- **橙色的框是"当前这段重复"**：被框住的节点一会儿要被整段摘掉。框里节点上面那条橙线（`curr`）会往右跑，而下面那条绿线（`prev`）**一动不动** —— 这个错位就是本题的全部难点；
- **摘链那一帧**：`prev` 伸出一条橙色虚线弧，跨过整段重复节点落到 `curr` 上，那条弧就是 `prev.next = curr` 这个赋值。被摘的节点同时变灰、被打上删除线。

## 四、完整推演表

用动画里的例子：

```
pool 下标: 0=1  1=2  2=3  3=3  4=4  5=4  6=5
1 → 2 → 3 → 3 → 4 → 4 → 5
```

| 帧 | phase | prev | curr | 动作 | 说明 |
|---|---|---|---|---|---|
| 0 | init | dummy | 1 | — | 架好 `dummy`，`prev` 落在它身上 |
| 1 | scan | dummy | 1 | — | `1` 的下一个 `2` 不同值，安全 |
| 2 | scan | 1 | 2 | `prev` 前进 | `2` 的下一个 `3` 不同值，安全 |
| 3 | **dup-start** | 2 | 3 | 发现重复 | `3` 和下一个 `3` 同值，**段长 2**；`prev` 从此停住 |
| 4 | skip | 2 | 3 | `curr` 前进 | 后面还有同值的 `3`，重复段没走完 |
| 5 | skip | 2 | 4 | `curr` 前进 | 跨出重复段 —— 此刻 `curr` 在 `4` |
| 6 | **unlink** | 2 | 4 | `prev.next = curr` | 两个 `3` 一起被摘掉，`prev` 仍在 `2` |
| 7 | advance | 3 | 4 | `prev` 前进 | `prev` 跟到 `curr` 位置上，即将又发现重复 |
| 8 | **dup-start** | 3 | 4 | 发现重复 | 第二段重复开始，**段长 2** |
| 9 | skip | 3 | 4 | `curr` 前进 | 后面还有同值的 `4` |
| 10 | skip | 3 | 5 | `curr` 前进 | 跨出重复段，`curr` 在 `5` |
| 11 | **unlink** | 3 | 5 | `prev.next = curr` | 两个 `4` 被摘掉 |
| 12 | advance | 4 | 5 | `prev` 前进 | 现在 `prev` 在 `5` 上 |
| 13 | scan | 4 | 5 | — | `5` 没有下一个，安全 |
| 14 | **done** | dummy | ∅ | 返回 | `curr` 到 ∅，返回 `dummy.next` → **`1 → 2 → 5`** |

数一下每一帧的 prev 是否合理：第 3–6 帧 `prev` 一直是 `2`（**四个帧没动过**），第 8–11 帧一直是 `3`。**"发现重复 → prev 冻结"在这张表里一眼可见。**

> 表里 `skip` 帧的 `curr` 有时和上一帧显示同一个值 —— 那是因为**这一帧的动作是"从上一个节点走到当前节点"**，画面停在走完之后的位置。`dup-start` 是"发现重复"的宣告帧，`skip` 才是真正执行移动的帧，两者职责不同。

再看 `1 → 1 → 1 → 2 → 3`（头节点就要被删的场景）：

| 帧 | phase | prev | curr | 动作 | 说明 |
|---|---|---|---|---|---|
| 0 | init | dummy | 1 | — | 注意 `prev` 是 **dummy**，不是 head |
| 1 | **dup-start** | dummy | 1 | 发现重复 | 第一个 `1` 和第二个 `1` 同值，**段长 3** |
| 2 | skip | dummy | 1 | `curr` 前进 | 后面还有同值的 `1`，重复段没走完 |
| 3 | skip | dummy | 1 | `curr` 前进 | 还剩一个同值的 `1` |
| 4 | skip | dummy | 2 | `curr` 前进 | 跨出重复段，`curr` 到 `2` |
| 5 | **unlink** | dummy | 2 | `dummy.next = 2` | 三个 `1` 一起被摘 —— **`head` 自己就被删了** |
| 6 | advance | 1 | 2 | `prev` 前进 | `prev` 落到保留下来的 `2` 上 |
| 7 | scan | 1 | 2 | — | `2` 的下一个 `3` 不同值，安全 |
| 8 | scan | 2 | 3 | `prev` 前进 | `3` 没有下一个，安全 |
| 9 | **done** | dummy | ∅ | 返回 | **`2 → 3`** |

第 5 帧是整题的题眼：**被删的是原来的头节点，而执行删除的是 `dummy.next = 2`**。没有 dummy，这一步根本写不出来。

## 五、阿里变体：重复的只留一个

面经里的变体是：**保留重复元素只留一个**，`1→1→1→2→3→3→4` 变成 `1→2→3→4`。

注意它是"重复过的值留一个、没重复过的值照常留"，不是"每个值都留一个"（后者是 LC 83）。对 `1,1,1,2,3,3,4` 来说两者恰好结果不同：

| 规则 | `1,1,1,2,3,3,4` 的结果 |
|---|---|
| **LC 82**（重复的全删） | `2, 4` |
| **阿里变体**（重复的留一个，没重复的照留） | `1, 2, 3, 4` |
| **LC 83**（每个值都留一个） | `1, 2, 3, 4` |

改法只有一处：**接回去的时候不要接到 `curr`，接到重复段的最后一个节点上**。

```python
class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev, curr = dummy, head

        while curr:
            if curr.next and curr.val == curr.next.val:
                dup_val = curr.val
                last = curr                  # 记住这一段的最后一个
                while curr and curr.val == dup_val:
                    last = curr              # 一路更新，"最后"自然浮出来
                    curr = curr.next
                prev.next = last             # ★ 唯一的改动：接 last 而不是 curr
                prev = last                  # prev 也落到这个保留节点上
            else:
                prev = curr
                curr = curr.next

        return dummy.next
```

`1→1→1→2→3→3→4` 走一遍：三个 `1` 里留下第三个，`prev` 落到它身上；`2` 没重复，照常过去；两个 `3` 里留下第二个；`4` 照常留。结果 `1 → 2 → 3 → 4`。

> 面试里遇到这种"变体"，**先把规则复述一遍再动手**。"重复的留一个"和"每个值留一个"听起来像，结果可能一样也可能不一样 —— 拿 `1,1,1,2` 试一下就知道差别了。主动说出这层区别，比直接写代码得分高。

## 六、Java 版

```java
class Solution {
    public ListNode deleteDuplicates(ListNode head) {
        ListNode dummy = new ListNode(0, head);
        ListNode prev = dummy, curr = head;

        while (curr != null) {
            if (curr.next != null && curr.val == curr.next.val) {
                int dupVal = curr.val;
                while (curr != null && curr.val == dupVal) {
                    curr = curr.next;          // 整段跳过
                }
                prev.next = curr;              // 一次摘掉；prev 不动
            } else {
                prev = curr;                   // 确认安全，prev 才前进
                curr = curr.next;
            }
        }
        return dummy.next;
    }
}
```

Java 里注意 `curr.val == curr.next.val` 用的是 `int` 比较，`==` 没问题（如果是 `Integer` 装箱类型就要用 `.equals`，别踩这个坑）。

## 七、边界情况

| 输入 | 结果 | 说明 |
|---|---|---|
| `[]` | `[]` | `curr` 一开始就是 `null`，循环不进 |
| `[1]` | `[1]` | 没有下一个，走 `else` 分支保留 |
| `[1,1]` | `[]` | 头节点整段被删，`dummy.next` 变 `null` |
| `[1,1,1]` | `[]` | 三连全删 |
| `[1,1,2]` | `[2]` | **头节点被删** —— dummy 在这里救命 |
| `[1,2,2]` | `[1]` | **尾节点被删** —— 内层 `curr and` 在这里救命 |
| `[1,2,3]` | `[1,2,3]` | 完全无重复，原样返回 |
| `[1,1,2,2]` | `[]` | 两段重复，全删 |
| `[1,2,2,3,3,4]` | `[1,4]` | 中间两段重复 |

两个"救命"的点值得单独记：

- **`[1,1,2]`** 验证 **dummy 必要性**：删除动作落在头节点上，`prev` 是 dummy。把 dummy 去掉、直接 `prev = head` 起手，这个用例就会崩。
- **`[1,2,2]`** 验证 **内层 `while curr and ...` 的 `curr and`**：重复段延伸到链表末尾，`curr` 会走到 `None`。漏掉这个判断，`curr.val` 直接 `AttributeError`（Java 里是 `NullPointerException`）。

## 八、复杂度

- **时间 `O(n)`**：外层 `while curr` 让 `curr` 从左到右走一遍；内层的 `while curr and curr.val == dup_val` 也在推同一个 `curr`，**不是嵌套的独立循环** —— 每个节点在整个过程中最多被 `curr` 访问一次。加起来仍是 `O(n)`。
- **空间 `O(1)`**：只多了 `dummy`、`prev`、`curr` 三个变量（Java 里还有内层的 `dupVal`）。没有哈希表、没有递归栈。

> 那个"内层循环为什么不算嵌套"是很好的加分点。判断方法：看内层循环有没有用到**外层之外的独立游标**。这里内层推的就是外层的 `curr`，所以是"同一个指针多走几步"，摊还下来仍是线性。

## 九、常见坑

**1. 忘了 dummy，或者返回了 `head`。**

```python
prev, curr = head, head      # 错的！head 自己要被删时无从下手
...
return head                  # 错的！head 可能已经是孤儿节点
```

这是这题第一大坑。判断标准很简单：**只要删除动作可能落在头节点上，就必须架 dummy，且返回 `dummy.next`**。

**2. `prev` 在重复时跟着 `curr` 一起前进了。**

```python
if curr.next and curr.val == curr.next.val:
    while curr and curr.val == curr.val:
        prev = curr          # 错的！prev 不该动
        curr = curr.next
    prev.next = curr
```

`prev` 是"接回点"，必须留在重复段的**前一个**位置。跟着推进的话，中间几个被摘节点会卡在 `prev` 和 `curr` 之间。

**3. 内层循环漏掉 `curr and`。**

```python
while curr.val == dup_val:    # 错的！重复段到末尾时 curr 变 None，直接崩
```

必须写成 `while curr and curr.val == dup_val`。

**4. 把重复段的判据写成"值在整条链里出现过"。**

```python
seen = set()                 # 错的！这不是 82 的语义
for node in ...:
    if node.val in seen: ...
```

排序链表上判重**只看邻位就够**，不需要统计全局。写成全局统计既慢（要开 `O(n)` 空间）又容易把 82（全删）和 83（留一个）搞混。

**5. 和 LC 83 的条件搞混。**

| 题 | 发现重复时 | 结果 |
|---|---|---|
| **LC 83** | `prev.next = curr.next`（删当前） | 每个值留一个 |
| **LC 82** | 整段跳到段外，再 `prev.next = curr` | 重复值一个不留 |

记法：**83 是"踩掉重复的那一个"，82 是"整段铲走"**。82 多了一层"先找到段尾"的循环，代码长一点，语义干净得多。

**6. 忘了这题不用递归。**

递归写链表题很省事，但这题递归要处理的"当前节点是否属于重复段"需要向前看、还要正确回接，写出来比迭代绕得多。而且递归栈是 `O(n)`，虽然题目没要求 `O(1)`，但迭代版本来就更短更清晰。

## 十、面试怎么答

**开口 30 秒给思路**（别一上来就写代码）：

> 链表已经排序，所以重复的一定挨在一起，判重只看邻位就行。难点是"重复的节点一个都不留"，意味着重复段的第一个节点也要删 —— 而它可能是头节点，头节点没有前驱。所以先在头上架一个 dummy 当它的人造前驱。然后双指针：`prev` 是"最后一个确定保留的节点"，`curr` 往前探。发现 `curr.val == curr.next.val` 就记住这个值，让 `curr` 一路跳到重复段之外，再 `prev.next = curr` 一次把整段摘掉 —— 这一步 `prev` 不能动。没重复的时候才 `prev = curr` 一起前进。最后返回 `dummy.next`。时间 O(n)，空间 O(1)。

**然后主动交代三个易错点** —— 这是区分"背过答案"和"真懂"的地方：

1. **dummy 是为了让"删头节点"变成一次普通删除**，返回必须用 `dummy.next`；
2. **`prev` 只在确认 `curr` 不属于重复段时才前进**，摘链时它必须停在重复段前面；
3. **内层循环要写 `while curr and curr.val == dup_val`**，重复段拖到末尾时 `curr` 会变 `None`。

**追问应对**：

- *"内层那个 while 不会让复杂度变成 O(n²) 吗？"* —— 不会。内外两层推的是**同一个 `curr`**，每个节点只被访问一次，摊还是 `O(n)`。
- *"能不用 dummy 吗？"* —— 能，但要单独处理"头节点开始的重复段"：先用一个 while 把头部的重复整段删掉，再进入主循环。多一段特判代码，不如 dummy 干净。
- *"如果要求重复的留一个呢？"* —— 接回的时候接 `last`（重复段最后一个节点）而不是 `curr`，其余不变。这就是那个阿里变体。
- *"复杂度为什么不是 O(n) 空间？"* —— 排序保证重复相邻，所以不需要哈希表统计；全程只有三个指针变量。
- *"这题和 LC 83 的区别？"* —— 83 每个值留一个（`prev.next = curr.next`），82 重复的一个不留（整段跳到段外）。82 多了找段尾的内层循环。

## 结语

把链表系列串起来看，这题的位置是这样的：

| 题 | 核心动作 | 和本题的关系 |
|---|---|---|
| **LC 206** 反转链表 | 迭代三行原地反转 | 都靠"先记住再改指" |
| **LC 19** 删除倒数第 N 个 | 快慢指针固定间隔 | **同样靠 dummy 解决"删头节点"** |
| **LC 83** 删除排序链表重复元素 I | 每个值留一个 | **只差一行条件**，本文的反面 |
| **LC 82** 删除排序链表重复元素 II | 整段跳过后一次摘掉 | 本文，dummy 的必要性最直观的一题 |
| **LC 160** 相交链表 | 交换游标 | 那题比**引用**，这题比**值**，判据各跟着题走 |

这题最值得带走的东西，不是那 15 行代码，而是这个反射：

> **看到"可能要删头节点"，先架 dummy。**

同样的反射在 LC 19 上是"可能要删头节点"，在 LC 143、234 上是"可能要断开/反转后半段"。链表题的很多麻烦，都是在处理"边界节点没有前驱/没有后继"这类结构缺陷 —— 而**造一个假节点**，往往是成本最低的通用解法。

```
dummy → 1 → 1 → 2
        ↑
   head 没有前驱，删不动；
   给它一个 dummy，就删得动了。
```

下次再遇到"这个操作在头节点上会失效"的链表题，先问自己一句：**能不能在它前面凭空造一个节点？**
