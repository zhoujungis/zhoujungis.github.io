LC 93, restore IP addresses: segment backtracking with two layers of pruning

2026-09-26 · 12 min · Stack Frame

The problem

A valid address is four integers from zero to 255 separated by dots, with no leading zeros in any part. Given a digit string, return every valid address it can form.

"25525511135"  ->  ["255.255.11.135", "255.255.111.35"]
"0000"         ->  ["0.0.0.0"]
"010010"       ->  ["0.10.0.10", "0.100.1.0"]

Backtracking is combination enumeration written recursively

Cutting the string into four pieces means choosing three of the gaps, and with at most three digits per piece the string length must lie between four and twelve. That bounds the number of candidate cut sets to at most 165, so the search space is a constant. Backtracking here is organisation, not a performance strategy.

What deserves design is the pruning, and it comes in two independent layers.

LayerQuestionExample
Segment validityIs this piece acceptable?Above 255, or a leading zero
FeasibilityCan this path still succeed?The first piece is a single digit, but ten digits remain and three pieces hold at most nine

The second layer is where the efficiency comes from and it is the one most often omitted. Without it the answers are still correct, since dead ends simply fail later, but many subtrees are searched for nothing. The single-digit first piece is the clearest illustration: the piece itself is entirely legal and the mistake is only visible when looking ahead.

The recursion

def restoreIpAddresses(s: str) -> list[str]:
    ans = []
    n = len(s)

    def dfs(pos: int, path: list[str]) -> None:
        if len(path) == 4:
            if pos == n:
                ans.append('.'.join(path))
            return
        remain_segs = 4 - len(path)
        for seg_len in (1, 2, 3):
            if pos + seg_len > n:
                continue
            seg = s[pos:pos + seg_len]
            if seg[0] == '0' and seg_len > 1:
                continue
            if int(seg) > 255:
                continue
            rest = n - pos - seg_len
            segs = remain_segs - 1
            if segs > 0 and not (segs <= rest <= segs * 3):
                continue
            dfs(pos + seg_len, path + [seg])

    if 4 <= n <= 12:
        dfs(0, [])
    return ans

Three details. The fourth piece must consume exactly the remaining digits, since four pieces must cover the string neither more nor less. A single zero is legal and a zero followed by more digits is not, so the test is on length as well as the first character. And passing a fresh list down avoids manual popping, at the cost of copying, which is irrelevant at this scale.

For the leading-zero example the first piece can only be a single zero, and every longer option starting with zero is pruned, leaving two addresses.

Enumeration without recursion

def restoreIpAddresses(s: str) -> list[str]:
    n, res = len(s), []
    if not (4 <= n <= 12):
        return res
    for i in range(1, 4):
        for j in range(i + 1, i + 4):
            for k in range(j + 1, j + 4):
                if k >= n:
                    continue
                parts = (s[:i], s[i:j], s[j:k], s[k:])
                if all(valid(seg) for seg in parts):
                    res.append('.'.join(parts))
    return res

With a fixed number of levels and a fixed branching factor, the recursion and the triple loop are the same thing. Recursion earns its keep when the constraints are dynamic, such as an unknown number of segments or pruning that depends on the accumulated path. Either works here, and the recursive form is the more portable template when follow-ups arrive.

ProblemShared skeleton
Palindrome partitioningSame segmentation with a different validity test, plus a table precomputing palindromes

Letter combinations of a phone numberPure enumeration with no pruning

The template has four parts: make a choice, check validity, recurse, undo. And validity always splits into two questions, whether the choice itself is acceptable and whether the path can still lead anywhere.

Java

public List<String> restoreIpAddresses(String s) {
    List<String> ans = new ArrayList<>();
    int n = s.length();
    if (n < 4 || n > 12) return ans;

    dfs(s, 0, new ArrayList<>(), ans);
    return ans;
}

private void dfs(String s, int pos, List<String> path, List<String> ans) {
    if (path.size() == 4) {
        if (pos == s.length()) ans.add(String.join(".", path));
        return;
    }
    int remainSegs = 4 - path.size();
    for (int len = 1; len <= 3; len++) {
        if (pos + len > s.length()) continue;
        String seg = s.substring(pos, pos + len);
        if (seg.charAt(0) == '0' && len > 1) continue;
        if (Integer.parseInt(seg) > 255) continue;
        int rest = s.length() - pos - len;
        int segs = remainSegs - 1;
        if (segs > 0 && (rest < segs || rest > segs * 3)) continue;
        path.add(seg);
        dfs(s, pos + len, path, ans);
        path.remove(path.size() - 1);
    }
}

Parsing is safe because a segment is at most three characters. The path is shared, so the removal after recursion is mandatory.

Complexity

At most 165 cut sets and a linear join per candidate, with the input bounded at twelve digits, so the whole thing is effectively constant. The recursion depth is four and the path holds at most four pieces. That is what separates this from ordinary backtracking: pruning here avoids dozens of paths rather than reducing an exponential.

Common mistakes

  1. Pruning every segment starting with zero, which kills the all-zeros case. The condition must also require length above one.
  2. Not requiring the fourth piece to consume the remainder, which silently drops trailing digits and emits fake addresses.
  3. Parsing an empty segment, which happens when the cut indices are wrong.
  4. Forgetting to undo a shared path, which contaminates later answers.
  5. Omitting the feasibility check, which is not a bug but does lose marks when the interviewer asks what could be improved.
  6. Skipping the length precheck, which both saves work and states that the input is structurally impossible.

How to answer it

Characterise the search size first, then name the two pruning layers and stress the second, since it governs the case where a segment is legal and the path is not. Volunteer the two special rules, the fourth piece consuming exactly the rest and the single zero being legal. Note that the triple loop is equivalent here, and that recursion wins on portability. Then the complexity, which is constant, and the related problems with swapped validity tests.
