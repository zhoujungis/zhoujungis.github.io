LC 224 and 772, basic calculators: settle immediately, or wait your turn

2026-09-09 · 16 min · Stack Frame

The problems

224: evaluate an expression with digits, plus, minus, parentheses and spaces. 772: the same with multiplication and division, truncating division toward zero.

"(1+(4+5+2)-3)+(6+8)"   -> 23
"1 + 2 - (3 + 4) - 5"   -> -9
"2*(5+5*2)/3+(6/2+8)"   -> 21

These are the degenerate and full versions of one problem. With only addition and subtraction all operators share a precedence and associate left, so nothing waits, and the stack's only job is remembering what the enclosing level owes. Adding multiplication breaks that uniformity, and the waiting begins.

224: no precedence, so debts only

Since plus and minus are same-precedence and left-associative, a number's sign is fully determined by the time it is read, so it can be settled immediately. Two variables suffice: a running total for the current level, and the sign for the next number.

Parentheses are the only complication. Everything inside is a separate small expression, but its value is owed to the enclosing level, multiplied by the sign before the opening bracket. So push the outer state, reset the accumulator, and on the closing bracket fold the inner result back in.

def calculate(s: str) -> int:
    result, sign, stack = 0, 1, []
    i = 0
    while i < len(s):
        c = s[i]
        if c == ' ':
            i += 1
        elif c.isdigit():
            j = i
            while j < len(s) and s[j].isdigit():
                j += 1
            result += sign * int(s[i:j])
            i = j
        elif c == '+':
            sign = 1; i += 1
        elif c == '-':
            sign = -1; i += 1
        elif c == '(':
            stack.append((result, sign))
            result, sign = 0, 1
            i += 1
        else:
            inner = result
            prev, psign = stack.pop()
            result = prev + psign * inner
            i += 1
    return result

What goes on the stack is not an intermediate value but an outer debt: the accumulated total and the sign the bracket as a whole carries. For the second sample, opening the bracket pushes three and minus one, the inside evaluates to seven, and the merge gives three minus seven, which then continues with minus five to reach minus nine.

772: precedence breaks immediate settlement

With multiplication the old foundation collapses, because a number may now have to wait for a higher-precedence operator to its right. Two stacks are needed: one for operands and one for operators, the classic shunting-yard arrangement.

The single discipline: when a new operator arrives, pop and apply every operator on top whose precedence is greater than or equal to it, then push the new one.

Using greater-or-equal rather than strictly greater also handles left associativity. For ten minus two minus three, the second minus finds an equal on top and settles the first subtraction, which is correct; with a strict comparison it would be right-associative and wrong.

That discipline maintains a clean invariant: inside each level of brackets, the operator stack holds strictly increasing precedence. So flushing at the end by popping from the top down gives exactly the right order, since low-precedence operators have sunk to the bottom.

An opening bracket is a barrier that stops the arrival comparisons, and a closing bracket settles down to the barrier and then discards it.

def calculate(s: str) -> int:
    prec = {'+': 1, '-': 1, '*': 2, '/': 2}
    nums, ops = [], []

    def apply():
        op, b, a = ops.pop(), nums.pop(), nums.pop()
        if op == '+': nums.append(a + b)
        elif op == '-': nums.append(a - b)
        elif op == '*': nums.append(a * b)
        else:
            q = abs(a) // abs(b)
            nums.append(q if (a >= 0) == (b >= 0) else -q)

    i = 0
    while i < len(s):
        c = s[i]
        if c == ' ':
            i += 1
        elif c.isdigit():
            j = i
            while j < len(s) and s[j].isdigit():
                j += 1
            nums.append(int(s[i:j]))
            i = j
        elif c == '(':
            ops.append(c); i += 1
        elif c == ')':
            while ops[-1] != '(':
                apply()
            ops.pop()
            i += 1
        else:
            while ops and ops[-1] != '(' and prec[ops[-1]] >= prec[c]:
                apply()
            ops.append(c)
            i += 1
    while ops:
        apply()
    return nums[0]

The most instructive pair is the closing bracket followed by the division: inside the barrier two layers settle by their own precedence, and outside it the pending multiplication settles before the division is pushed. Each side of the barrier follows its own discipline.

Variants

  • No parentheses, with multiplication: the same shunting yard without the barrier branch, or the clever one-stack version that defers each number by one step and folds immediately when the pending operator is multiplicative.
  • Reverse Polish evaluation: the output side of the same machinery, where no precedence or parentheses exist and a single stack suffices. Writing it once makes the forward version obvious.
  • String decoding: the same bracket context stack with different payloads, a partial string and a repeat count instead of a total and a sign.
  • Recursive descent: three grammar rules translated into three functions, with precedence encoded in the call depth and brackets in the recursion. Cleaner to read, with an implicit stack.
  • Extensions: function calls, variables and exponentiation all amount to new entries in the operator stack and new rows in the precedence table.

Java

public int calculate(String s) {
    Deque<Long> nums = new ArrayDeque<>();
    Deque<Character> ops = new ArrayDeque<>();
    for (int i = 0; i < s.length(); ) {
        char c = s.charAt(i);
        if (c == ' ') { i++; }
        else if (Character.isDigit(c)) {
            long v = 0;
            while (i < s.length() && Character.isDigit(s.charAt(i)))
                v = v * 10 + (s.charAt(i++) - '0');
            nums.push(v);
        } else if (c == '(') { ops.push(c); i++; }
        else if (c == ')') {
            while (ops.peek() != '(') apply(nums, ops);
            ops.pop(); i++;
        } else {
            while (!ops.isEmpty() && ops.peek() != '('
                    && rank(ops.peek()) >= rank(c)) apply(nums, ops);
            ops.push(c); i++;
        }
    }
    while (!ops.isEmpty()) apply(nums, ops);
    return nums.pop().intValue();
}

Java division already truncates toward zero, unlike Python. Intermediate results are kept as 64-bit values because expressions can overflow a 32-bit integer mid-computation, and the conversion happens only at the end.

Edges

  • Spaces appear anywhere; skip them while scanning rather than splitting and filtering.
  • Multi-digit numbers must be accumulated, not read one digit at a time.
  • Single numbers and single brackets are valid and leave exactly one operand at the end.
  • Unary minus is not in the official data, but appears in variants. A sign at the start, after an opening bracket, or after another operator is part of the number, not an operator.
  • Division must truncate toward zero; Python floor division gives the wrong sign for negatives.
  • Division by zero does not occur in the test data.

Complexity

Both are linear in time and space. The stack depth equals the bracket nesting. The second version's cost deserves a note: one closing bracket can trigger several settlements, which looks quadratic, but each operator is popped exactly once in its lifetime, so the total is the number of operators, the same amortised accounting as the two-stack queue.

Common mistakes

  1. Using a strict comparison for precedence, which breaks left associativity on same-precedence chains.
  2. Using floor division in Python, which rounds the wrong way for negatives.
  3. Not handling unary minus, which consumes an operand that does not exist.
  4. Clearing the accumulator before pushing the outer state, which stores the wrong debt.
  5. Forgetting to discard the barrier after settling to it, which blocks every later comparison.
  6. Returning without flushing the operator stack.

How to answer it

Ask which switches the problem has: multiplication, brackets, unary signs. Then the simple version: same precedence, settle immediately, a stack only for outer debts. Then why that fails once precedence differs, and the two-stack discipline with the greater-or-equal comparison, the barrier, and the final flush. Then the three details that prove experience: truncation direction, 64-bit intermediates, and unary signs.

Closing

The stack family reaches its last piece here: one problem shows the stack storing debts, the other shows it adjudicating order. The mnemonic: equal precedence means settle immediately with a debt stack; unequal precedence means queue in two stacks and settle on arrival.

From bracket matching, through remembering history and flipping direction, to ordering by value and now settling by precedence, the same last-in-first-out structure has worn six faces, and every one was forced by the same reason: something cannot be handled now and cannot be thrown away.
