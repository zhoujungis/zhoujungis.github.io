The KMP next array: matching a string against itself

2026-10-14 · 18 min · Stack Frame

The problem

Find the next array of the pattern p = "abacaba", using the definition of the longest proper prefix that is also a suffix. The answer is [0,0,1,0,1,2,3].

One sentence before anything else: confirm which definition the interviewer is using. There is a second convention where the first entry is -1, from the classic data structures textbook, and under that convention the same string gives [-1,0,0,1,0,1,2]. The two differ by a single global shift, and the numbers reported are completely different.

p      = a  b  a  c  a  b  a
next   = 0  0  1  0  1  2  3      longest proper prefix equal to a suffix
other  = -1 0  0  1  0  1  2      the first-entry-minus-one convention

The exercise looks like memorising a template. The actual difficulty sits in a place that gets glossed over: which substring the value at next[i] describes. A vague definition, dropping the word proper or confusing inclusive and exclusive, shifts every answer by one; and once the table exists, next[j-1] is the index every fallback reads.

What next is, and why a string can match itself

Pin the definition down. next[i] is the length of the longest proper prefix of p[0..i] that is also a suffix of it.

Proper is the load-bearing word: neither the prefix nor the suffix may be the whole substring, so the length is strictly below i + 1. Because the trivial "the string equals itself" case is excluded, next[0] = 0 always holds, since a one-character string has no proper prefix or suffix.

  • p[0..2] = "aba": the prefix "a" equals the suffix "a", length one, so next[2] = 1.
  • p[0..3] = "abac": "a" against "c" and "ab" against "ac" both fail, so next[3] = 0.
  • p[0..6] = "abacaba": "aba" appears at both ends, so next[6] = 3.

The obvious method enumerates prefix lengths from large to small at every index, which costs quadratic time. KMP is one sentence:

Let the pattern match against itself. Treat p as both the text and the pattern, walk i along the text, and let j hold the length of the prefix already matched.

next[0] = 0; j = 0
for i = 1 .. n-1:
    while j > 0 and p[i] != p[j]:
        j = next[j-1]        # mismatch: fall back to a shorter candidate prefix
    if p[i] == p[j]:
        j = j + 1            # match: the candidate prefix grows by one
    next[i] = j

j has two faces, and understanding both removes the need to memorise anything.

First, it is the length of the matched prefix: before each comparison, the invariant p[0..j-1] equals p[i-j..i-1] holds. Second, it is the index of the next character to compare against p[i], because the first j characters are already aligned with the j characters immediately before i, so p[j] is the natural next candidate.

def prefix_function(p):
    n = len(p)
    next = [0] * n
    j = 0
    for i in range(1, n):
        while j > 0 and p[i] != p[j]:
            j = next[j - 1]
        if p[i] == p[j]:
            j += 1
        next[i] = j
    return next

# p = "abacaba" -> [0, 0, 1, 0, 1, 2, 3]

Three details decide correctness. The first entry is a definition, not a computation, so the loop starts at one. The fallback reads next[j-1] and not next[j], because the longest proper prefix-suffix of p[0..j-1] is exactly the shorter candidate that still fits. And the fallback is a loop rather than a branch, since one step may not be enough on a longer string.

One sentence captures the machine: j is the matched prefix length, p[0..j-1] stays aligned with p[i-j..i-1], a mismatch walks back along next[j-1], a match advances j, and the value is recorded as next[i].

The two definitions

A: prefix functionB: first entry minus one
next[0]0-1, a sentinel

Result for "abacaba"[0,0,1,0,1,2,3][-1,0,0,1,0,1,2]
 
B = [-1] + A[0 .. n-2]

B is A shifted one position right with a sentinel prepended. The reason anyone uses B is that it compiles the fallback into the table: under A the fallback is j = next[j-1], while under B it is j = next[j], and the -1 at the front expresses "there is nowhere left to go". The cost is one extra layer of indexing, since B[i] describes p[0..i-1] while A[i] describes p[0..i].

So open with the question and take the initiative back. Say which definition you are using, give the numbers under both, and note the single shift between them, then offer to switch.

The family of problems

KMP is one table plus one scan that never looks back, and the same skeleton answers a whole chain of questions.

  • LC 28, first occurrence of a pattern. The second pass itself, and the basis of built-in substring search.
  • LC 459, repeated substring pattern. No matching needed: the string is a repetition when the length divides by the period, tested as n % (n - next[n-1]) == 0 with next[n-1] > 0.
  • LC 214, shortest palindrome. Build the table for s + '#' + reverse(s) and read the last entry, which is the longest palindromic prefix.
  • LC 1392, longest happy prefix. The definition of next[n-1] exactly.
  • LC 686, repeated string match. The text may be constructed by repeating, and the bound follows from the length ratio.

Java

class Solution {
    public int[] prefixFunction(String p) {
        int n = p.length();
        int[] next = new int[n];
        int j = 0;
        for (int i = 1; i < n; i++) {
            while (j > 0 && p.charAt(i) != p.charAt(j)) {
                j = next[j - 1];
            }
            if (p.charAt(i) == p.charAt(j)) {
                j++;
            }
            next[i] = j;
        }
        return next;
    }
}

class Solution {
    public int strStr(String text, String p) {
        int m = text.length(), n = p.length();
        if (n == 0) return 0;
        int[] next = prefixFunction(p);
        int j = 0;
        for (int i = 0; i < m; i++) {
            while (j > 0 && text.charAt(i) != p.charAt(j)) {
                j = next[j - 1];
            }
            if (text.charAt(i) == p.charAt(j)) {
                j++;
            }
            if (j == n) {
                return i - n + 1;
            }
        }
        return -1;
    }

    private int[] prefixFunction(String p) {
        int n = p.length();
        int[] next = new int[n];
        int j = 0;
        for (int i = 1; i < n; i++) {
            while (j > 0 && p.charAt(i) != p.charAt(j)) j = next[j - 1];
            if (p.charAt(i) == p.charAt(j)) j++;
            next[i] = j;
        }
        return next;
    }
}

The sentinel convention changes two indices.

class Solution {
    public int[] prefixFunctionNegOne(String p) {
        int n = p.length();
        int[] b = new int[n];
        b[0] = -1;
        int j = -1;
        for (int i = 1; i < n; i++) {
            while (j >= 0 && p.charAt(i) != p.charAt(j + 1)) {
                j = b[j];
            }
            if (p.charAt(i) == p.charAt(j + 1)) {
                j++;
            }
            b[i] = j;
        }
        return b;
    }
}

The difference worth remembering: under A the index is a length, so p[j] is the next character to compare, while under B the index is a position, so p[j + 1] is. The tables still differ by one global shift.

Edge cases

  • A single character gives [0], and no code runs at all.
  • A string of identical characters gives [0,1,2,3], with no fallback.
  • A string with no equal prefix and suffix gives all zeroes.
  • The value at index i can never exceed i, because proper excludes the whole substring; a result of i + 1 means the constraint was dropped.
  • A miss returns minus one, not zero and not the last position.
  • A pattern longer than the text simply scans out.
  • An empty pattern returns zero, since the empty string is a prefix of everything; confirm that convention before answering.
  • Non-ASCII characters compare as UTF-16 units; anything outside the basic plane needs code-point iteration.

The linear claim is amortised and worth memorising: j increases by at most one per iteration, so total increases are bounded by the pattern length, and every fallback only returns what was previously added, so total fallbacks are bounded the same way. A single iteration can fall all the way to zero, but the sum across the loop is linear.

Common mistakes

  1. Dropping the word proper, which makes the value i + 1 and turns the fallback into an infinite loop. The single most common failure.
  2. Reading next[j] instead of next[j-1] under definition A, which lands on the wrong candidate.
  3. Writing the fallback as a branch rather than a loop.
  4. Mixing the two conventions, comparing against p[j] while falling back to next[j].
  5. Moving i backwards on a mismatch, which collapses the algorithm into brute force.
  6. Recomputing the table inside the search loop instead of once.
  7. Reading p[j] before checking whether j has already reached the pattern length.
  8. Believing next[i] describes p[0..i-1], which is the other convention.

How to answer it

Start by confirming the definition, and state both answers with the note that they differ by a shift. That demonstrates you know there are two conventions and hands the choice back.

Then describe the machine: the first entry is fixed by definition, the loop from one is a string matching itself, j is both the matched length and the next index to compare, the invariant holds between the aligned prefix and suffix, a mismatch walks back along the previous entry, a match advances, and each value is recorded at the end of its iteration.

Then justify the linear bound with the amortisation argument: increments are capped by the pattern length, fallbacks only undo increments, so the total work is proportional to the input.

Expect follow-ups: first occurrence, which is the search pass; whether a string is a repetition, which is arithmetic on the last entry; the longest palindromic prefix, which needs the reversed concatenation; and the longest prefix that is also a suffix, which is the last entry itself.

Close with the summary: one table and one scan that never looks back, where the table records the boundary information a string carries about itself, and the scan cashes in the equal prefix and suffix that were already inside the matched segment. The two definitions are simply two ways of writing the same table down.

Closing

The difficulty is not the code, which is six lines, but the definition. Whether the value at an index describes the substring up to and including it, and whether the first entry is zero or minus one, decides whether the answer is one list or the other. Ask first, then write.

And spend the remaining effort on understanding the sentence "a string matching against itself": one counter records how much has matched and simultaneously points at what to compare next; on a mismatch it walks back to a shorter candidate that still fits. Once the table exists, the scan never moves the text pointer back, which is the whole purchase: linear build, linear search.
