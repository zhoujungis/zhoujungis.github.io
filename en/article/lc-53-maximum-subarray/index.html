LC 53, maximum subarray: is carrying the prefix worth it

2026-09-28 · 15 min · Stack Frame

The problem

Find the contiguous subarray with the largest sum, containing at least one element.

[-2,1,-3,4,-1,2,1,-5,4]  -> 6   (the subarray 4,-1,2,1)
[1]                      -> 1
[5,4,-1,7,8]             -> 23

It looks harmless, since enumerating every subarray is obvious, and it is a standard interview question because those five lines hold three things: the way the DP state is defined, the correctness of the greedy decision, and the information merging that leads to segment trees.

The whole problem in one sentence

Scan left to right, maintaining one quantity: the maximum sum of a subarray ending at the current position.

At element x there are only two candidates: continue the previous run, or restart at x. Take the larger.

cur = max(x, cur + x)

This single line only ever asks one question: carrying the prefix, is it a gain or a loss.

Expanding the maximum shows the decision: if the running sum is non-negative, carrying it costs nothing; if it is negative, the prefix is a liability and is discarded, restarting at x. So the decision belongs to the prefix, not to x. The current element has no choice in the matter; it only determines what the sum becomes after joining.

A second variable records the largest value the running sum ever reached. Since every subarray ends somewhere, that maximum over all positions is the global answer.

def maxSubArray(nums):
    cur = best = nums[0]
    start = bestStart = bestEnd = 0

    for i in range(1, len(nums)):
        if cur < 0:
            cur = nums[i]
            start = i
        else:
            cur = cur + nums[i]
        if cur > best:
            best = cur
            bestStart, bestEnd = start, i

    return best, nums[bestStart:bestEnd + 1]

The value form and the position form are the same thing. The maximum is the shortest way to state it, but returning the subarray itself requires the positional form, because only there does the start index exist.

The initialisation is easy to get wrong: both variables start at the first element, not at zero, because the subarray must contain at least one element, and an all-negative array must answer with the largest negative rather than zero.

Why discarding a negative prefix is safe

Ask the reverse question: does discarding lose the optimum.

It does not. If the running sum is negative, any candidate ending at the current index that includes the prefix sums to the same continuation plus a negative number, so it is strictly worse than the candidate that starts fresh. Therefore the best candidate among those ending here never includes the negative prefix.

And the DP definition only cares about candidates ending here. Anything better that ended earlier was already recorded. So both possibilities are covered, and discarding loses nothing.

Restate it in one line: the running sum is the optimum subject to ending here, and discarding a negative prefix merely maintains that constraint.

Divide and conquer: four quantities

Splitting the array in half, the answer lies entirely left, entirely right, or crosses the midpoint as a suffix of the left part plus a prefix of the right. The third case is the awkward one, since a suffix sum cannot be derived from a subarray sum, so each interval carries three extra quantities.

i_sum = total
l_sum = best prefix sum
r_sum = best suffix sum
m_sum = best subarray sum

i_sum = L.i_sum + R.i_sum
l_sum = max(L.l_sum, L.i_sum + R.l_sum)
r_sum = max(R.r_sum, R.i_sum + L.r_sum)
m_sum = max(L.m_sum, R.m_sum, L.r_sum + R.l_sum)

def maxSubArrayDivide(nums):
    def get(l, r):
        if l == r:
            s = nums[l]
            return (s, s, s, s)
        mid = (l + r) // 2
        L = get(l, mid)
        R = get(mid + 1, r)
        i_sum = L[2] + R[2]
        l_sum = max(L[0], L[2] + R[0])
        r_sum = max(R[1], R[2] + L[1])
        m_sum = max(L[3], R[3], L[1] + R[0])
        return (l_sum, r_sum, i_sum, m_sum)

    return get(0, len(nums) - 1)[3]

A widely repeated error about its complexity: many sources claim linearithmic. Merging is constant work and the recursion tree has about twice as many nodes as elements, so the total is linear, the same class as the linear scan. The linearithmic figure belongs to the naive version that rescans the interval on every merge. With the four quantities cached, merging is constant.

Its value is never speed, since the constant is larger and it uses logarithmic stack space. Its value is extensibility: those four quantities are exactly what a segment tree maintains, so if the problem becomes point updates with arbitrary range queries, the linear scan is hopeless and this becomes a tree with logarithmic update and query.

In one line: the scan computes and forgets, while the divide and conquer stores the merge rule, which makes it a data structure rather than an algorithm.

Variant: the circular version

In a circular array a subarray may wrap around. Split by whether it does: unwrapped is the ordinary answer, and wrapped means the complement of a contiguous gap, so maximising the wrapped part means minimising the gap.

[ part1 | smallest gap | part2 ]
wrapped sum = total - minSum

The gap must be contiguous, so the problem reduces to the minimum subarray sum, which is the same scan with minimum instead of maximum.

def maxSubarraySumCircular(nums):
    total = 0
    cur_max = max_sum = nums[0]
    cur_min = min_sum = nums[0]

    for x in nums:
        cur_max = max(x, cur_max + x)
        max_sum = max(max_sum, cur_max)
        cur_min = min(x, cur_min + x)
        min_sum = min(min_sum, cur_min)
        total += x

    if max_sum < 0:
        return max_sum
    return max(max_sum, total - min_sum)

The all-negative case is the only hidden rock. There the smallest gap is the entire array, so the wrapped candidate is zero, which corresponds to the empty subarray and is illegal. Hence the early return of the ordinary answer.

[-3,-2,-3] -> the gap is everything, so return -2
[5,-3,5]   -> the gap is -3, so total minus it is 10, from the wrapped pair

The initialisation follows the same rule: both running maxima and minima start at the first element, since an all-negative answer is a single negative value.

The first row is the one worth remembering: the best profit from one purchase and one sale is the maximum subarray sum of the adjacent differences, which collapses the whole stock series into this problem.

class Solution {
    public int maxSubArray(int[] nums) {
        int cur = nums[0], best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            cur = Math.max(nums[i], cur + nums[i]);
            best = Math.max(best, cur);
        }
        return best;
    }
}

  1. Starting both variables at zero, which answers zero for an all-negative array.
  2. Resetting on a zero running sum. The sum is the same either way, but the range is not, and the reported subarray gains a useless prefix. The test must be strictly negative.
  3. Forgetting the all-negative guard in the circular version, which answers zero instead of the largest negative.
  4. Starting the circular running extremes at zero, with the same consequence.
  5. Copying the single-variable scan into the product version, where the minimum must also be tracked because two negatives multiply positive.
  6. Believing the divide and conquer version is linearithmic. The merge is constant, so the total is linear, and computing that on the spot is worth more than reciting a table.

How to answer it

Give the state definition first: the maximum sum of a subarray ending here, where the anchor on the ending index is what reduces the transitions to two. Then the sentence behind the line: carrying the prefix is a gain or a loss. Then the correctness argument, which most people skip: with a negative prefix every candidate containing it is worse, so the optimum ending here excludes it, and earlier optima are already recorded.

Asked to return the subarray, describe the positional form with the start index recorded on reset and the best range recorded on improvement. Asked about divide and conquer, give the four quantities and the three sources for the answer, note that merging is constant so the total is linear, and point out the segment tree upgrade. Asked about the circular version, explain the complement, the minimum subarray, and the all-negative guard. And connect the stock problem through the difference array.

Closing

The shorter the code, the more it reveals. There is one decision point in that line, with three layers behind it: two candidates at the surface, a state anchored on the ending index in the middle, and a liability argument underneath.

Divide and conquer enters from another direction, saying that storing the merge rule lets you answer repeatedly, which yields a segment tree; and the circular version says that running the same algorithm backwards turns wrapping into digging a hole.

assert maxSubArray([-2,1,-3,4,-1,2,1,-5,4]) == 6
assert maxSubArray([-3,-1,-2]) == -1
assert maxSubArray([1]) == 1
assert maxSubArray([5,4,-1,7,8]) == 23
assert maxSubarraySumCircular([5,-3,5]) == 10
assert maxSubarraySumCircular([-3,-2,-3]) == -2
