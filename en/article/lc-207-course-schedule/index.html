LC 207, course schedule: in-degrees and a queue, or three colours and a back edge

2026-10-12 · 15 min · Stack Frame

The problem

Given a number of courses and a list of prerequisite pairs, decide whether all courses can be completed. Each pair says the second course must be taken before the first.

numCourses = 4, prerequisites = [[1,0],[2,0],[3,1],[3,2]]
-> true, and a valid order is [0,1,2,3] or [0,2,1,3]

numCourses = 2, prerequisites = [[1,0],[0,1]]
-> false, since each waits for the other

Pin the direction first, which is the biggest trap here. A pair listing a then b means b must come first, so the edge runs from b to a, from prerequisite to dependent. Getting that backwards is not cosmetic; it decides the correctness of every in-degree and every order that follows.

With that fixed, the whole problem is one sentence: a course order is a topological order of the directed graph, and completing everything is possible exactly when the graph has no cycle.

What remains is two machines for detecting cycles and producing an order: in-degree peeling with a queue, and three-colour depth-first search.

Topological order and cycles

A topological order is a linear arrangement where every edge points from earlier to later. That is precisely a valid course order, with every prerequisite ahead of what depends on it.

  • A topological order exists exactly when the graph is acyclic. With a cycle, the courses on it wait for each other, so there is no answer.
  • The order is usually not unique. The example admits both listed orders, because courses one and two are independent.
  • An isolated course is always available first, since its in-degree is zero.

Two mirror approaches. Peeling repeatedly takes any course with in-degree zero, then decrements its dependents, which naturally emits a topological order. Colouring walks the edges, and an edge back into the recursion stack signals a cycle, while reversing the post-order yields the order.

In-degree peeling

The in-degree of a course is how many prerequisites it still waits on, so zero means it is available now. The algorithm: take every course with in-degree zero, then relax its dependents.

from collections import deque

def canFinish(numCourses, prerequisites):
    adj = [[] for _ in range(numCourses)]
    indegree = [0] * numCourses
    for a, b in prerequisites:
        adj[b].append(a)
        indegree[a] += 1
    q = deque(v for v in range(numCourses) if indegree[v] == 0)
    order = []
    while q:
        cur = q.popleft()
        order.append(cur)
        for nxt in adj[cur]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                q.append(nxt)
    return len(order) == numCourses

The criterion is that the number of courses emitted equals the total. If only courses on a cycle remain, their in-degrees never reach zero, the queue runs dry early, and the emitted count falls short.

Three colours

White means unvisited, grey means currently on the recursion stack, black means finished and known safe. Walking an edge to white descends; to black it is skipped, since that route was already verified; to grey it means the edge points back into the current stack, so a cycle is caught.

def canFinish_dfs(numCourses, prerequisites):
    adj = [[] for _ in range(numCourses)]
    for a, b in prerequisites:
        adj[b].append(a)
    color = [0] * numCourses
    order = []

    def dfs(v):
        color[v] = 1
        for nxt in adj[v]:
            if color[nxt] == 1:
                return False
            if color[nxt] == 0 and not dfs(nxt):
                return False
        color[v] = 2
        order.append(v)
        return True

    for v in range(numCourses):
        if color[v] == 0 and not dfs(v):
            return False
    return True

Two things matter. Grey and black must be distinguished, because a single visited flag treats a black neighbour, which is a safe convergence, as a cycle and reports a false positive. And the order is the reversal of the post-order, since a node is appended after all its dependents, so prerequisites land at the end and move to the front when reversed.

Note that the two machines produce different orders, and both are correct. Topological orders are not unique; each machine simply picked a different valid one.

Java

class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
        int[] indegree = new int[numCourses];
        for (int[] p : prerequisites) {
            adj.get(p[1]).add(p[0]);
            indegree[p[0]]++;
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int v = 0; v < numCourses; v++) {
            if (indegree[v] == 0) queue.offer(v);
        }
        int done = 0;
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            done++;
            for (int nxt : adj.get(cur)) {
                if (--indegree[nxt] == 0) queue.offer(nxt);
            }
        }
        return done == numCourses;
    }
}

The colouring version keeps an array of three states, returns false on a grey neighbour, and sets black after the loop. Recursion depth is bounded by the number of courses, which is fine at two thousand and would need an explicit stack beyond that. The version that returns an order appends on completion and reverses at the end.

The family

  • Course schedule two. Return the order: the dequeue sequence directly, or the reversed post-order.
  • Alien dictionary. Build edges between letters from the first differing position of adjacent words, then sort. The graph construction is the difficulty, not the sort.
  • Minimum height trees. On an undirected graph, repeatedly peel degree-one leaves, the same idea as peeling in-degrees, and the one or two survivors are the roots.
  • Find eventual safe states. Peel out-degree-zero nodes on the reversed graph; whatever remains is on or behind a cycle. This is the mirror image of peeling in-degrees.
  • Sort items by groups. Two topological sorts, one within groups and one between them.
  • Sequence reconstruction. Decide whether the order is unique, which happens exactly when the queue never holds more than one candidate.

Line them up and the template never changes: compute degrees, repeatedly remove zero-degree nodes, or colour the graph. What differs is where the edges come from, prerequisites or letters or a reversed graph, and what is returned at the end.

Edges

  • A self-loop leaves a course waiting on itself, so its in-degree never drops and the answer is false.
  • Duplicate edges inflate the in-degree, which is relaxed twice and still arrives at zero, so the result is correct but worth knowing.
  • An isolated course is available immediately and changes nothing.
  • One course with no prerequisites returns true, with order consisting of that course.
  • With no prerequisites at all, the identity order is already a valid topological order.
  • Multiple components are handled naturally by the queue, while the depth-first version must start from every unvisited node.
  • A branch hanging off a cycle is also stuck, since it waits on a prerequisite on the cycle. The criterion is the emitted count, not a direct detection of nodes on the cycle.

Building the graph is linear in the number of pairs, and each node and edge is processed once. Early exit on a cycle does not change the worst case.

Common mistakes

  1. Reversing the edge direction, which flips the entire order.
  2. Forgetting to decrement dependents, or enqueueing them before the count reaches zero.
  3. Using an empty queue as the cycle test. It empties after a successful run too; the criterion is the emitted count.
  4. Using a single visited flag in the depth-first version, which misreports safe convergences as cycles.
  5. Returning the post-order without reversing it.
  6. Deep recursion on a chain-shaped graph; use an explicit stack or the queue version.
  7. Returning a partial order when a cycle exists, without checking the count first.
  8. Mixing duplicate-edge handling with set-based graph construction, which changes the in-degrees.
  9. Starting the depth-first search from one node only, which misses other components.
  10. Assuming the topological order is unique. Uniqueness is a separate problem, decided by whether the queue ever holds two candidates.

How to answer it

Give the translation first: the question is whether a directed graph has a cycle. Fix the edge direction from the pairs, then pick a machine, peeling zero in-degree courses and counting the emitted total, or colouring and reporting a grey back edge. Both are linear.

Then volunteer the order-returning variant, which is where candidates separate: the dequeue sequence is an order, and the reversed post-order is the other. Note that the order is not unique, and give an example, which shows you understand that a valid order is not a unique one.

Then connect the follow-ups: uniqueness, graph construction from letters, leaf peeling on an undirected graph, and out-degree peeling on the reversed graph.

Close with one sentence: the course order is a topological order, finishing is acyclicity, and in-degree peeling and grey back edges are two equivalent machines for saying that.

Closing

The whole difficulty collapses into one translation. Prerequisites are directed edges, a valid order is a topological order, and a cycle is a set of courses that can never be finished. Peeling makes the currently available courses explicit in a queue, and colouring makes the unfinished path explicit in a stack, and both reach the same criterion: peel or walk everything and there is no cycle.

What separates answers is three small things: the direction must not be reversed, grey and black must be distinguished, and the post-order must be reversed.
