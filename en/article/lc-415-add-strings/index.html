LC 415, add strings: translating long addition into code

2026-09-29 · 12 min · Stack Frame

The problem

Add two non-negative integers given as strings, returning a string, without using any big-integer library or converting the whole string to a number.

"456" + "77"  ->  "533"

Elimination, not obstruction

The prohibition is not a trick: it removes the shortcut of converting to numbers, leaving only the column addition learned in primary school. What the interviewer wants to see is whether a procedure you already know can be translated into code without losing anything.

    1 1
    4 5 6
+     7 7
-------
  5 3 3

Units: six plus seven is thirteen, write three and carry one. Tens: five plus seven plus one is thirteen, write three and carry one. Hundreds: four plus zero plus one, with num2 having no hundreds digit, write five and stop.

Three phrases: start at the units, write the digit and carry the rest, and treat a missing position as zero. In code that is two pointers from the ends plus a carry variable.

Three implementation points

For alignment, pad the shorter string or decide by index. Indexing avoids the copy and one line handles it, and the key reading is that a used-up side contributes zero for that column rather than being skipped.

sum   = a + b + carry
out   = sum % 10
carry = 1 if sum >= 10 else 0

The carry can only be zero or one, because nine plus nine plus one is nineteen, which never reaches twenty. That is a property of adding two non-negative decimal digits and can be exploited rather than generalised.

Then the loop condition, which is the easiest thing to omit:

while i >= 0 or j >= 0 or carry > 0:

The first two clauses cover remaining digits, and the third covers a final carry that has to grow a new digit. For "999" plus "1" the two strings are exhausted while the carry is still one, so omitting it yields "000" instead of "1000".

def addStrings(num1: str, num2: str) -> str:
    i, j = len(num1) - 1, len(num2) - 1
    carry = 0
    res_low_to_high = []

    while i >= 0 or j >= 0 or carry > 0:
        a = ord(num1[i]) - 48 if i >= 0 else 0
        b = ord(num2[j]) - 48 if j >= 0 else 0
        s = a + b + carry
        res_low_to_high.append(s % 10)
        carry = 1 if s >= 10 else 0
        i -= 1
        j -= 1

    return ''.join(map(str, reversed(res_low_to_high)))

Two implementation details. Digit characters are contiguous in their encoding, so subtracting the code for zero converts one character at a time, which is not the forbidden whole-string conversion. And the result is appended low to high and reversed at the end, since column addition naturally produces digits in that order; inserting at the front instead would make each step linear and the whole thing quadratic.

Variants

With signs, the skeleton is unchanged and a dispatch layer wraps it. Split sign from magnitude, and if the signs agree, add the magnitudes and keep the sign. If they differ, compare magnitudes first by length and then lexicographically, subtract the smaller from the larger, and take the sign of the larger magnitude.

Subtraction mirrors addition with one extra idea, borrowing, where a negative intermediate adds ten and sets the borrow. It also produces leading zeros, which must be stripped on return, keeping a single zero when everything cancels.

For multiplication, the digit at position i of one string times the digit at position j of the other lands at position i plus j plus one in the result, which is the whole trick, and carries accumulate the same way. The multiplication problem is this problem with several layers per column.

def multiply(num1: str, num2: str) -> str:
    if num1 == "0" or num2 == "0":
        return "0"
    m, n = len(num1), len(num2)
    res = [0] * (m + n)
    for i in range(m - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            mul = (ord(num1[i]) - 48) * (ord(num2[j]) - 48)
            p1, p2 = i + j, i + j + 1
            total = mul + res[p2]
            res[p2] = total % 10
            res[p1] += total // 10
    k = 0
    while k < len(res) - 1 and res[k] == 0:
        k += 1
    return ''.join(map(str, res[k:]))

The family rule: digit-by-digit processing, a carry or borrow variable, and the three-clause loop condition constitute the whole big-number family. Only the base, the storage direction and the work per column vary.

public String addStrings(String num1, String num2) {
    int i = num1.length() - 1, j = num2.length() - 1, carry = 0;
    StringBuilder sb = new StringBuilder();

    while (i >= 0 || j >= 0 || carry > 0) {
        int a = i >= 0 ? num1.charAt(i) - '0' : 0;
        int b = j >= 0 ? num2.charAt(j) - '0' : 0;
        int s = a + b + carry;
        sb.append(s % 10);
        carry = s >= 10 ? 1 : 0;
        i--; j--;
    }
    return sb.reverse().toString();
}

Complexity

Linear in the longer length, one addition per column plus possibly one more for the carry. Extra space is constant, since only a carry and two pointers exist, with the result string being the required output rather than an auxiliary structure.

Common mistakes

  1. Omitting the carry clause, which loses the final digit for inputs like nine hundred ninety-nine plus one.
  2. Skipping the exhausted side instead of contributing zero, which drops the longer string's remainder and the carry with it.
  3. Using the character directly in arithmetic, which is a type error, or converting the whole string, which the problem forbids.
  4. Building the result by inserting at the front, which is quadratic; append and reverse instead.
  5. Not stripping leading zeros in the subtraction and multiplication variants, remembering to keep one zero when everything cancels.
  6. Applying the digit conversion to a sign character, which silently computes a negative digit. Split the sign before entering the digit loop.

How to answer it

Characterise it as elimination rather than obstruction. Then state the three implementation points before writing, with the loop condition third and emphasised, since that is the sentence worth the most. Then offer the overflow example to show awareness that a carry can grow a digit. Then the complexity, and finally the two extensions, signed addition and multiplication, with the placement formula.
