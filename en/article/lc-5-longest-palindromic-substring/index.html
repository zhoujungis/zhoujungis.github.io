LC 5, longest palindromic substring: two n minus one centres

2026-09-29 · 12 min · Stack Frame

The problem

Find the longest palindromic substring.

"babad"  ->  "bab"    ("aba" is equally valid)
"cbbd"   ->  "bb"

Enumerate centres, not substrings

Count the brute force first: quadratically many substrings, each verified in linear time, so cubic overall, which is a billion operations at a thousand characters.

Change the viewpoint. A palindrome is symmetric about a centre, so it is fully determined by the centre and the radius. The answer is therefore the longest expansion over all centres, and there are only twice n minus one of them, each expanding in linear time at worst. That gives quadratic time and constant space.

Why not n centres: palindromes come in two parities.

Centre typeExampleCount
Character centreOdd palindromesn
Gap centreEven palindromes, symmetric about the seam between two charactersn minus one

Enumerating only character centres loses every even palindrome, since the centre of a four-letter palindrome is not on any character. That is the classic bug in this problem.

The expansion

def expand(s, l, r):
    while l > 0 and r < len(s) - 1 and s[l - 1] == s[r + 1]:
        l -= 1
        r += 1
    return l, r

The loop assumes the centre is already valid and tests whether the next pair outward matches, comparing the characters one step outside the current bounds, with guards preventing an out-of-range read.

def longestPalindrome(s: str) -> str:
    n = len(s)
    best_l, best_r = 0, 0

    for i in range(n):
        l, r = expand(s, i, i)
        if r - l > best_r - best_l:
            best_l, best_r = l, r
        if i + 1 < n and s[i] == s[i + 1]:
            l, r = expand(s, i, i + 1)
            if r - l > best_r - best_l:
                best_l, best_r = l, r

    return s[best_l:best_r + 1]

Two details. The gap centre is only expanded when the two adjacent characters are equal, since otherwise even the smallest even palindrome is impossible. And equal-length candidates keep the first found, which makes the result predictable rather than dependent on enumeration order.

For the four-letter example the character centres all give length one and the gap between the two middle letters expands to the pair, which is where the second sample answer comes from. For a four-letter palindrome the gap expands outward further, reaching the full string.

Comparisons

def longestPalindrome(s: str) -> str:
    n = len(s)
    dp = [[False] * n for _ in range(n)]
    best_l, best_r = 0, 0
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            dp[i][j] = s[i] == s[j] and (j - i < 2 or dp[i + 1][j - 1])
            if dp[i][j] and j - i > best_r - best_l:
                best_l, best_r = i, j
    return s[best_l:best_r + 1]

The interval DP has the same time and quadratic space, so centre expansion wins on memory while the DP offers a different lens, that larger palindromes grow from smaller ones. Mention it and write the other.

Manacher runs in linear time by inserting separators to unify the parities and reusing already computed radii. It is low value to hand-write in an interview; naming it and its two ideas is enough unless the role demands it.

ProblemWhat changes
Count palindromic substringsThe same centres, counting instead of taking the maximum
Longest palindromic subsequenceSubsequences may skip characters, so centre expansion fails and interval DP takes over
Palindrome partitioningA precomputed palindrome table plus backtracking

The family rule: contiguous means enumerate centres, and subsequence means interval DP. The dividing line is whether an inside-out extension can derive the answer.

Java

public String longestPalindrome(String s) {
    int n = s.length(), bestL = 0, bestR = 0;
    for (int i = 0; i < n; i++) {
        int[] odd = expand(s, i, i);
        if (odd[1] - odd[0] > bestR - bestL) { bestL = odd[0]; bestR = odd[1]; }
        if (i + 1 < n && s.charAt(i) == s.charAt(i + 1)) {
            int[] even = expand(s, i, i + 1);
            if (even[1] - even[0] > bestR - bestL) { bestL = even[0]; bestR = even[1]; }
        }
    }
    return s.substring(bestL, bestR + 1);
}

private int[] expand(String s, int l, int r) {
    while (l > 0 && r < s.length() - 1 && s.charAt(l - 1) == s.charAt(r + 1)) {
        l--; r++;
    }
    return new int[]{l, r};
}

Complexity

Quadratic time for the centres and their expansions, constant space, which is an order of magnitude better than the DP and the practical reason to prefer it.

Common mistakes

  1. Enumerating only character centres, which answers a single character for the even samples. Self-test on the four-letter even case.
  2. Comparing the current bounds instead of the next pair outward, which walks off the string because the centre pair trivially matches itself.
  3. Updating equal-length candidates, which makes the result drift with enumeration order.
  4. Treating a failing gap as a candidate, which records an interval that is not a palindrome. Test the two characters first.
  5. Getting the DP base case off by one, which misclassifies a two-character palindrome, and filling the table in the wrong order.
  6. Splitting by UTF-16 code units in JavaScript, which breaks emoji apart so that identical characters compare unequal.

How to answer it

Characterise first: a palindrome is determined by centre and radius, so enumerate the twice-n-minus-one centres. State that number explicitly, with the split into character centres and gap centres, and note that omitting gaps loses every even palindrome. Then the brute-force accounting and how centre expansion folds verification into enumeration. Then the comparisons with the DP and with Manacher, and finally the edge cases.
