Splitting a sequence to maximise the sum of variances

2026-10-13 · 13 min · Stack Frame

The problem

Given a sequence, cut it into a fixed number of contiguous segments so that the sum of the segments' variances is maximised.

a = [2, 8, 3, 9, 4, 7], k = 2  ->  14.6875
cut after the second element: variance of [2,8] is 9.00,
variance of [3,9,4,7] is 5.6875

Two things are worth digging into: the answer defies intuition, since splitting into two segments often gives a larger total than not splitting at all, and the performance depends entirely on one prefix-sum identity. Without it the solution is cubic.

Cutting makes it larger

The whole sequence has variance 6.92, and the best two-segment split reaches 14.69, more than double. Variance measures distance from a mean, and in the whole sequence the value eight and the value three pull in opposite directions and cancel. Split into two groups and each gets its own mean, so the deviations that cancelled are now amplified separately.

So the instinct that finer cuts reduce the sum is wrong, and it is wrong in the opposite direction. The maximum usually occurs where the segments are internally spread out and their means are close together.

One identity always holds and helps decide when two formulations coincide: the total sum of squared deviations decomposes into the within-group and between-group parts. When segments are equal length, maximising the within-group variance is exactly minimising the between-group part, in other words pulling the segment means together. With unequal lengths the conversion fails, and the DP still works, but the shortcut is gone.

Constant-time segment variance

dp[i][j] = max over k of dp[k][j-1] + var(k+1 .. i)
dp[i][1] = var(1 .. i)
dp[0][0] = 0
answer   = dp[n][k]

For two segments this degenerates to a single scan over cut points, which is the first layer of the DP.

S1[i] = a[1] + ... + a[i]
S2[i] = a[1]^2 + ... + a[i]^2

for segment (l, i], length len = i - l:
  sum  = S1[i] - S1[l]
  mean = sum / len
  var  = (S2[i] - S2[l]) / len - mean * mean

The last line is the definition written as the mean of squares minus the square of the mean, and it makes the inner loop two array reads and one multiply-subtract.

The last row shows a single-element segment, whose variance is necessarily zero. That is why the answer with as many segments as elements is zero, and it is the boundary most often forgotten.

Generalising to k segments

def max_variance_sum(a, k):
    n = len(a)
    S1 = [0] * (n + 1)
    S2 = [0] * (n + 1)
    for i in range(1, n + 1):
        S1[i] = S1[i - 1] + a[i - 1]
        S2[i] = S2[i - 1] + a[i - 1] * a[i - 1]

    def var(l, r):
        length = r - l
        if length <= 0:
            return 0.0
        s = S1[r] - S1[l]
        q = S2[r] - S2[l]
        return q / length - (s / length) * (s / length)

    NEG = float('-inf')
    dp = [[NEG] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 0.0
    for i in range(1, n + 1):
        for j in range(1, min(i, k) + 1):
            best = NEG
            for m in range(j - 1, i):
                if dp[m][j - 1] == NEG:
                    continue
                cand = dp[m][j - 1] + var(m, i)
                if cand > best:
                    best = cand
    return dp[n][k] if k <= n else None

The cost is quadratic in the length times the number of segments. If segment lengths have a lower bound, or the optimal cut point is monotone, divide-and-conquer or slope optimisation removes the inner loop, but write the cubic-free version correctly first.

If the problem asks for the minimum, which is the more common industrial form used in binning, image segmentation and k-means-style cost functions, only the comparison and the sentinel change.

Java

public static Double maxVarianceSum(int[] a, int k) {
    int n = a.length;
    if (k > n) return null;
    double[] s1 = new double[n + 1];
    double[] s2 = new double[n + 1];
    for (int i = 1; i <= n; i++) {
        s1[i] = s1[i - 1] + a[i - 1];
        s2[i] = s2[i - 1] + (double) a[i - 1] * a[i - 1];
    }
    final double NEG = Double.NEGATIVE_INFINITY;
    double[][] dp = new double[n + 1][k + 1];
    for (double[] row : dp) java.util.Arrays.fill(row, NEG);
    dp[0][0] = 0.0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= Math.min(i, k); j++) {
            double best = NEG;
            for (int m = j - 1; m < i; m++) {
                if (dp[m][j - 1] == NEG) continue;
                int len = i - m;
                double sum = s1[i] - s1[m];
                double sq = s2[i] - s2[m];
                double mean = sum / len;
                best = Math.max(best, dp[m][j - 1] + sq / len - mean * mean);
            }
            dp[i][j] = best;
        }
    }
    return dp[n][k] == NEG ? null : dp[n][k];
}

The cast before squaring matters: an integer squared overflows a 32-bit type at modest magnitudes, so the sum of squares must live in a wider type.

Edges

  • One segment gives the variance of the whole sequence, which is the baseline for comparison.
  • As many segments as elements gives zero, since every segment is a single point.
  • More segments than elements is infeasible, so return a null result rather than raising.
  • A constant sequence gives zero under any split.
  • With negative values the formula is unchanged, though the mean may be negative, so do not take absolute values.
  • Population variance divides by the length. Sample variance divides by one less, has no value for a single-point segment, and breaks the case of maximal segmentation, so agree on the convention first.

Greedy is not an option: the cut with the largest left variance does not give the largest total, so there is no monotone relationship between a locally good segment and the global answer, and only enumeration with a table is safe.

Common mistakes

  1. Recomputing each segment's variance from scratch, which turns linear into quadratic and the general case into cubic in the length.
  2. Mixing population and sample variance, which breaks the additivity the DP relies on and divides by zero at maximal segmentation.
  3. Assuming finer cuts reduce the sum, which the sample numbers refute directly.
  4. Integer overflow in the sum of squares, or catastrophic cancellation when subtracting two large nearly equal means under floating point.
  5. Forgetting that single-point segments have zero variance, which affects the answer at maximal segmentation and the lower bound of the inner loop.
  6. Assuming maximisation, when the industrial formulation is usually minimisation.

How to answer it

Give the recurrence, then the constant-time variance identity with the two prefix sums, then the counterintuitive point with the numbers, then the decomposition identity and when it converts maximisation into minimisation. Then the boundaries: one segment, maximal segments, infeasible counts, and single-point variance. Then the variants, including the minimisation form, a lower bound on segment length, and the optimisation techniques.

Closing

The skeleton is small: one recurrence and one formula. What it really tests is whether you trust a counterintuitive answer, since splitting doubles the total because each segment's mean amplifies deviations that used to cancel, and whether you are willing to derive the constant-time variance rather than leave a linear scan inside the loop.
