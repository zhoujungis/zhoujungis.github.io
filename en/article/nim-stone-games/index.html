Nim and its relatives: one line of xor decides the game

2026-09-06 · 12 min · Stack Frame

The problem

Several piles of stones, two players alternating. On each turn a player takes any positive number of stones from any one pile. Whoever takes the last stone wins, and a player with no legal move loses. Decide whether the first player wins.

[3, 4, 5]  ->  true, since 3 xor 4 xor 5 is 2, which is not zero

Two relatives are asked more often than the general form. One gives a row of piles and allows taking a whole pile only from either end, with an even number of piles. The other has a single pile with a cap on how many stones may be taken per turn.

All three look like game theory and sit at three different levels: one line of xor, one parity argument, and one modulo. This article covers them in that order, and breaks the xor criterion into two arguments short enough to memorise.

Compress the piles into one number

The difficulty in these games is never computation but finding a state to recurse on. Each pile allows taking between one and its size, so the state space is far too large to search.

The classic result instead assigns each position a number: xor all the pile sizes together. The first player wins exactly when that value is nonzero.

Why it holds rests on two complementary arguments. When the xor is nonzero, there is always a move to a position with xor zero, which is a construction. And when the xor is zero, every move leads to a nonzero value: suppose changing one pile from p to a smaller value kept the total at zero, then that pile's contribution would be unchanged, meaning the value did not actually change, a contradiction.

Together they give an induction. The first player can always hand back a zero position, and whatever the second player does necessarily returns a nonzero one. The total number of stones strictly decreases, so the game ends, and the player who makes the last move is the first.

That is the definition of a losing position: not one where no move exists, but one where every move hands the win to the opponent.

Constructing the winning move

def first_player_wins(piles) -> bool:
    x = 0
    for p in piles:
        x ^= p
    return x != 0

def winning_move(piles):
    x = 0
    for p in piles:
        x ^= p
    if x == 0:
        return None
    h = x.bit_length() - 1
    for i, p in enumerate(piles):
        if (p >> h) & 1:
            piles[i] ^= x
            return piles

Take the highest set bit of the total, find a pile that has a one in that position, which must exist since otherwise the total could not have one there, and replace that pile with its xor against the total.

The new value is legal because both the pile and the total have a one at that bit, so the xor clears it, and all higher bits match and are unchanged. Hence the new value is strictly smaller and non-negative.

The case where the three piles are one, two and three is worth running by hand: the xor is always zero, the verdict is a first-player loss, and the strategy described is a mirror, answering whatever the opponent removes so that the xor returns to zero.

Check the second argument on the resulting position: the xor is zero, so any move by the opponent breaks it, for example taking one stone from the pile of four gives a total of seven, and the first player simply repeats the construction.

The even-pile variant

Restricting moves to taking an entire pile from either end, with an even number of piles, kills the xor criterion, since choices are now positional. But there is a cleaner result: the first player always wins, and the strategy is decided once at the start.

Colour the piles by their original index, even and odd. If the first move takes the left end, then from that point on both ends of the remaining row are odd-indexed. Taking the right end instead leaves only even indices available.

So the first move chooses which parity band the player will occupy for the whole game. Compute the sum of both bands, take the larger, and select the end that secures it. For the sample the even band sums to nine and the odd band to eight, so taking the left end locks in the win.

The animation colours the two bands and shows the taken piles degrading into dashed shells with their scores, the two sums side by side, and the winner lit. Note that the opponent plays greedily, taking the larger end each time, and still loses, because the strategy does not depend on the opponent.

With an odd number of piles the trick fails, since the two ends then have different parities and a single choice cannot lock a whole band, and interval dynamic programming is required, where the state records the advantage the first mover can obtain on a subarray.

Java

public static boolean firstPlayerWins(int[] piles) {
    int x = 0;
    for (int p : piles) x ^= p;
    return x != 0;
}

public static int[] winningMove(int[] piles) {
    int x = 0;
    for (int p : piles) x ^= p;
    if (x == 0) return null;
    int h = Integer.highestOneBit(x);
    for (int i = 0; i < piles.length; i++) {
        if ((piles[i] & h) != 0) {
            piles[i] ^= x;
            return piles;
        }
    }
    return null;
}

For the even-pile variant the answer is a single line returning true, though an interview requires the parity argument rather than the literal line.

Edges

  • A single pile wins if it is non-empty and loses if it is empty.
  • An empty position has xor zero and no move, so the player to act loses.
  • Two equal piles have xor zero and lose, with the mirror strategy taking the same amount from the other pile.
  • An empty pile among others is dead weight and is ignored by the xor.
  • For the even-pile variant, an odd number of piles breaks the conclusion and requires dynamic programming.

The time goes into understanding the criterion, not into computing it. Every verdict here is linear or constant, and the difficulty is reducing a position to a single number.

Common mistakes

  1. Reversing the convention. The standard rule is that taking the last stone wins; the misère variant reverses it, and when every pile has size one the outcome flips by the parity of the pile count. Interviewers like to switch conventions verbally.
  2. Choosing the wrong pile for the winning move. It must be one with a one at the total's highest set bit; choosing arbitrarily can increase the pile, which gifts stones to the opponent.
  3. Treating a zero xor as a draw rather than a loss. The opponent has an explicit mirroring strategy, so it is not luck.
  4. Applying the parity argument to general Nim. It holds only for end-taking with an even number of piles, because it depends on locking one band with the first move.
  5. Writing the modulo rule as a division, or using the cap itself rather than the cap plus one.
  6. Using the xor verdict on constrained variants that no longer allow taking any number from any pile; those need minimax or dynamic programming.

How to answer it

State the criterion with its name and complexity. Then both halves of the argument, the construction and the contradiction. Then the three construction steps rather than a claim of existence. Then the even-pile variant with the parity bands and the note that odd counts require interval DP. Then the family: the single-pile modulo rule, the golden-ratio losing positions of the two-pile game, misère Nim, and Sprague-Grundy for general impartial games.

Closing

The teaching value of these games is entirely in reduction: a huge space of pile configurations compresses into one xor value, giving a one-line verdict and a three-step construction. The even-pile variant shows that changing the constraint changes the invariant, from an xor to two parity bands. The work is never search, it is finding the invariant.
