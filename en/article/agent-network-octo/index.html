Agents Have Their Own Internet Now

🤝 This time it isn't computers that got networked — it's a group of Agents that actually know how to get work done. Once a group of Agents can divide labor, communicate, hand off, review, and let experience accumulate, the way organizations work truly starts to be rebuilt.

Introduction: From Standalone AI to an Agent Network

In the past, using AI felt more like each of us spinning up our own standalone machine. Claude Code writes code, Codex runs tasks, another Agent does research, and yet another Agent edits documents. Each one is capable enough, but most of the time they work in isolation — the context for a single project ends up scattered across multiple terminals, and nobody knows what anyone else did, changed, or got stuck on. Which raises the question: When one person has one Agent, that's a productivity tool. When an organization starts to have ten, a hundred, or even more Agents, things get a lot less simple. At that point they need a network — one that can divide labor, communicate, hand off, review, and distill the experience of every collaboration into something that accumulates. That is exactly the opening that MiningLamp Technology is aiming at with its open-source release of Octo. In the example below, you only need to hand a task to a single Agent, and it will automatically bring the other Agents along to work on it together:

Put simply, what Octo wants to be is an open-source, trustworthy Agent collaboration network — a single collaboration system that people, Agents, and external tools all enter together:
  • Open — open and self-hostable
  • Context — let work context flow through collaboration
  • Taste — keep human judgment, preferences, and taste on the record
  • Orchestration — orchestrate people, Agents, and tools in one collaboration layer
In a single sentence: Agents do. Humans decide. Behind that sentence sits a key shift in the next stage of AI applications: AI is no longer just answering questions in a chat box. It is entering organizational processes and becoming a digital workforce that can be assigned work, managed, and held to acceptance criteria.

What Three Core Concepts Does an Agent Network Need?

The first thing Octo has to do is give an Agent a desk it can take inside organizational collaboration. That comes down to three core concepts: Bot, Channel/Thread, and Matter.

🔹 Bot — Giving Each Agent a Business Card

In Octo, an Agent isn't a feature button you invoke ad hoc. It joins the team as a Bot identity, complete with an identity, a business card, a description of what it can do, and a work record. A Bot that's strong at writing code may be mediocre at documentation; another Bot that does solid research may be better suited to writing industry reports. If every Agent is nothing more than an entry point in a chat box, the organization has a hard time knowing who is good at what, who has done what, and whose output is more reliable. That is the problem Bot solves. It turns an Agent from a tool entry point into a digital colleague. Every Bot has its own AgentCard, with an owner, capability boundaries, and a work history. You can connect mainstream Agent tools such as OpenClaw, Hermes, Codex, Claude Code, and WorkBuddy, and manage them all uniformly as Bots inside the same system.

🔹 Channel & Thread — Where You Collaborate, and What You're Collaborating On

Channel is best understood as a project group or work channel. People and Bots align on intent, discuss approaches, assign tasks, and track progress in the same channel. What separates it from an ordinary group chat is that an Agent isn't just @-mentioned to come back with one line. It can receive context, join the discussion, and keep pushing the task forward. Channel answers the question of “where do we collaborate.” Thread is one specific piece of work. In a product launch project, for example, you might have a communications plan, an engineering write-up, website copy, a customer case study, and an FAQ all under discussion at the same time. If every message piles into one group, they get washed out fast. The value of Thread is keeping the background, the discussion, and the final conclusion of a single matter in the same place.

🔹 Matter — Turning Chat into Delivery

Matter addresses “how do we turn chat into action, and action into delivery.” Many people have had this experience with AI tools: the conversation flows smoothly and you feel the AI has understood; but once it's over, everything is still scattered across the chat window. You're the one who has to copy it out, tidy it up, create tasks, chase progress, and check the output. Matter's approach: when follow-up work emerges in a discussion, an Agent can summarize the key points, and once a human confirms, turn them into a matter. That matter has an owner, deliverables, acceptance criteria, and a complete record running from the brief through the discussion, the output, the feedback, and the acceptance decision. In other words, the work AI does finally has a place to be delivered. It no longer just hands you a paragraph of answer — it pushes the work into a state that can be tracked, reviewed, and signed off.

What Are the Six Multi-Agent Collaboration Modes?

Mention multi-agent today and many people picture the same scene: spin up a group, drop a few Agents in, and let them talk it over. That is one form of collaboration, but it's nowhere near enough. Collaboration in real work is complicated — some tasks need open discussion, while others need to be done independently so Agents don't influence each other; some need to be built and then reviewed, some need to move down a pipeline; and some are best run as several parallel attempts so you can pick whichever works best. Octo lays out six collaboration modes directly:

1️⃣ Solo — One Bot, Done

A single Bot completes the task on its own. Good for small tasks with clear boundaries and a well-defined goal — rewriting a piece of copy, cleaning up meeting notes, adding a code comment.

2️⃣ Roundtable — Open Discussion

Several Bots discuss the same question openly, each able to see the others' views. Good for brainstorming, multi-angle analysis, topic selection, and strategic judgment. Take a product-launch topic: you can have a technical Bot, a user-facing Bot, and a business Bot each give their read, then have the Leader converge them.

3️⃣ Critic — Independent Review

One Bot builds, another Bot reviews. The reviewer can send it back for rework. Good for quality-sensitive work such as code review, fact-checking, poking holes in a proposal, or flagging contract risk. The key to this mode is keeping “building” and “reviewing” separate. After all, in a real company we wouldn't have the same person draft the document and give the final sign-off. Once AI collaboration enters real work, it needs similar checks and balances.

4️⃣ Pipeline — Assembly Line

A finishes and hands off to B; B finishes and hands off to C. Each step's output is the next step's input. Good for multi-step tasks with a clear order — research first, then analysis, then a report, then polishing it into something publishable.

5️⃣ Split — Divide and Conquer

Break the large task into pieces, have different Bots process them in parallel, and let the Leader merge the results at the end. Good for tasks with a lot of material and relatively independent modules. For an industry study, one Bot can cover overseas companies, one can cover domestic companies, one can cover the technology roadmap, and you consolidate at the end.

6️⃣ Swarm — Compete, Then Pick

Send the same brief to several Bots, let each complete it independently, then choose the stronger result. Good for creative tasks — headlines, visual concepts, campaign planning, product naming.

Taken together, these six modes show that what Octo is solving isn't simply getting Agents to chat. What it really handles is the structural problem of organizational collaboration — who can see which information, who owns which step, who reviews, who merges, and when a human has to make the call. Previously these rules were mostly held up by people. In an era with ever more Agents, the collaboration system itself has to have them written in. This is also where Octo differs from traditional IM tools. Tools like Feishu, Slack, and DingTalk were designed primarily for person-to-person work — they excel at messaging, meeting coordination, and document flow. But once Agents become work subjects too, the system has extra problems to handle: AI identity management, AI task tracking, AI collaboration modes. Old tools can certainly bolt AI capabilities on, but if the number of Agents keeps growing, hanging an AI entry point next to the chat box will eventually not be enough.

Four Surfaces: Putting Octo Where the Work Happens

For a collaboration platform to actually get used, a philosophy isn't enough. It has to get into people's day-to-day work. In product form, Octo covers several entry points: Web App, mobile (iOS/Android), browser extension, and CLI. Wherever people work, that's where Agents should show up.

🌐 Web App — The Full Collaboration Workbench

Channels, Matters, Bot work records, and project progress can all be managed in one place. Good for driving complex projects, and for managing a digital team made up of multiple Bots.

📱 Mobile — Feedback and Acceptance

Plenty of AI tasks don't need you watching the whole time, but the key moments do need your decision. When a Bot hands back a milestone, for example, you glance at it on your phone, approve it if it's good, or send it back for more work if it isn't. This kind of lightweight judgment fits mobile perfectly.

🧩 Browser Extension — Summon an Agent Where the Work Is

The value of the browser extension isn't in moving your Feishu docs, GitHub Issues, and web reports into Octo. What it does is summon an Agent right beside the page you're already working in, and bring the current page context along with it. Say you're reading an industry report: select a passage and have a Bot summarize, translate, or rewrite it. Say you're looking at a GitHub Issue: have a Bot break down a repair plan based on the current problem. Say you're stuck in a document: summon a Bot to draft the next version for you. The payoff is that your workflow doesn't get interrupted. AI tools have historically asked users to switch windows, copy context, and re-describe the task. The browser extension shortens that step — wherever you work, the Agent stands by.

⌨️ CLI — Built for Developers and Native Agent Operation

For developers, a lot of work already happens in the terminal. Through the CLI, Agent tasks hook into command-line workflows, which suits anything involving code, automation, or runtime environments especially well. So Octo's product thinking is not about having an organization tear everything down and start over. It's more like adding, across documents, code platforms, project-management tools, browser pages, and terminals, a connection layer where people and Agents collaborate together. This also explains the emphasis on open source and private deployment. For an enterprise, the genuinely valuable AI asset is usually not any single answer, but the business context, collaboration records, preference judgments, and working methods behind it. Left to accumulate on a third-party platform, that material is hard for the enterprise to truly own; accumulated in the enterprise's own environment, it can become a long-term asset.

How We Collaborate Is Being Rebuilt in the Agent Era

There is a bigger judgment behind Octo. What the AI era is rebuilding is not just individual tools, but how we collaborate. Organizational collaboration used to happen mainly between people and people. In the future it will very likely happen between people and people, people and Agents, and Agents and Agents, all at the same time. That raises a very practical question: where exactly should people stand? Treat AI as a smarter search box and people still have to break down the task, organize the process, and check the result themselves; AI just answers faster. But treat Agents as a digital workforce and the human role changes — you don't have to execute every step in person, but you do have to set direction at the key moments, define standards, make judgments, and review results. That is what “Agents do. Humans decide.” means. Agents handle thinking, analysis, generation, execution, and scheduling; humans decide what's right, what's good, and what fits the business trade-offs. You kick off the task, and the Bot drives execution. The Bot hands back a milestone, you sign off. Not satisfied? Send it back. Satisfied? Approve it. Every annotation, rejection, and preference choice you make keeps shaping how the Bot works the next time around. That forms a flywheel: assign task → review and give feedback → accumulate preferences and skills → work more efficiently next time. In Octo, every collaboration accumulates three kinds of assets:
  • Context — project background, past decisions, discussion records. New members or new Bots don't have to align from zero.
  • Taste — every sign-off, rejection, annotation, and style choice records what you and your team actually like, endorse, and reject.
  • Skill — the conventions for writing code, the structure for a report, the template for a retrospective. These ways of working can be reused across the organization.
These are also the four letters of O.C.T.O. we mentioned a moment ago — Open, Context, Taste, Orchestration. Strung together, these four dimensions mean Octo wants to be more than an AI office tool. It looks more like a layer of organizational infrastructure for the PrivateAI era. Because once AI genuinely takes part in the work, what enterprises care about isn't only “is this model smart.” The more critical questions are:
  • Where does my data live?
  • Can my collaboration experience accumulate?
  • Will my organization's style be lost the next time the model changes?
  • Can my Agents understand the business better the more they're used?
Looked at that way, the significance of Octo going open source isn't just giving developers one more project to try out. It represents a trend — AI applications are migrating from “personal productivity tools” toward “organizational collaboration networks.”

Conclusion: Let Agents Be Colleagues, Not Just Assistants

A strong Agent can make one person more productive. Only when a group of Agents can collaborate under a shared set of rules does it start to be possible to change how an organization works. The internet released real network effects only once computers were connected to one another. In the Agent era, a similar question comes around again — when every person, every team, and every business process has Agents in it, who connects them? Octo's answer is to put Agents into organizational collaboration first. Give them identity, a desk, tasks, sign-off, and records, along with preferences and skills that build up piece by piece. In the end, Agents don't truly enter a company because they can say a few clever things in a chat box. They enter because they can take the work, push it forward, hand the results back, and understand this organization a little better with every round of feedback. Only when Agents stop working solo does AI really have a chance to go from assistant to colleague.
