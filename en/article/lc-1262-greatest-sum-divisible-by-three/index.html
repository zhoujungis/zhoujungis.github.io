LC 1262, greatest sum divisible by three: pick everything, then shave

2026-10-12 · 13 min · Stack Frame

The problem

Choose any subset whose sum is divisible by three and return the largest such sum, or zero if none exists.

[3,6,5,1,8]  -> 18   (3 + 6 + 1 + 8)
[4]          -> 0
[1,2,3,4,4]  -> 12

Clear up the most common misreading first: the subset may be any size, not exactly three. The sample uses four numbers. The three in the title refers to divisibility, and the only real constraint is that the chosen sum is congruent to zero modulo three.

All elements are positive, which matters: the total is an upper bound on any subset sum, so the only task is to discard the smallest worthwhile handful. Two approaches are worth knowing, and they contrast nicely: a greedy pass grouping by remainder, which relies on the positive precondition, and a three-cell rolling DP, which does not.

Take everything, then shave

Let the total be S with remainder r. If r is zero, S itself is the answer. Otherwise the discarded set must have sum congruent to r, and the elements are bucketed by their remainder, sorted ascending. Elements with remainder zero are never discarded, since that is pure loss.

Total remainderOptions
1Discard one element of remainder one, or two of remainder two
2Discard one element of remainder two, or two of remainder one
 
def maxSumDivThree(nums):
    total = sum(nums)
    r = total % 3
    if r == 0:
        return total
    m1 = sorted(x for x in nums if x % 3 == 1)
    m2 = sorted(x for x in nums if x % 3 == 2)

    def two(bucket):
        return bucket[0] + bucket[1] if len(bucket) >= 2 else float('inf')

    if r == 1:
        drop = min(m1[0] if m1 else float('inf'), two(m2))
    else:
        drop = min(m2[0] if m2 else float('inf'), two(m1))

    return 0 if drop == float('inf') else total - drop

Two details decide it. The buckets must be ascending and only the smallest entries matter, since discarding less is always better. And the two-element candidate must be infinite when the bucket is too short, because returning zero there would claim a free discard and the minimum would take a path that does not exist.

Why only those two shapes

Suppose the discarded set sums to something congruent to r. Looking only at each element's remainder, remainder-one contributes one and remainder-two contributes two.

Single elements give the remainder directly. For two elements, one plus one gives two, two plus two gives one, and a mixed pair gives zero, which fixes nothing. So to obtain r from two elements they must both come from the complementary bucket.

Three or more is worse in every case: either it contains three of the same kind, whose remainders cancel to zero and contribute nothing, or it reduces to one of the smaller combinations. Since all elements are positive, discarding more always means a smaller sum, so larger sets are dominated.

Hence the smallest cost is always either one element of remainder r or two of the complement, and considering only those two makes the code complete.

The DP route

The greedy collapses once negatives are allowed, since the total is no longer an upper bound. The DP stays linear and does not care about signs.

def maxSumDivThree(nums):
    NEG = float('-inf')
    dp = [0, NEG, NEG]
    for x in nums:
        old = dp[:]
        rem = x % 3
        for j in range(3):
            if old[j] == NEG:
                continue
            k = (j + rem) % 3
            dp[k] = max(dp[k], old[j] + x)
    return dp[0]

Three details. Snapshot before writing, which is the zero-one knapsack rule of using each item once; without it the same element can be read back and used twice. Use negative infinity rather than zero for unreachable states, or they appear reachable with sum zero. And only three states exist because there are only three remainders, so space is constant.

The relationship is that the DP is the general solution and the greedy is its specialisation to positive inputs, faster and simpler but with a precondition that cannot be broken. In an interview, give the greedy idea and then add the DP for the signed case.

The family

  • Subarrays with sum divisible by k: prefix sums plus congruence, counting equal-remainder pairs.
  • Shortest subarray whose removal makes the sum divisible by p: the same bucket idea with a shortest contiguous segment instead of fewest elements.
  • Check if pairs are divisible by k: remainders must be complementary, which is the same grouping action.
  • Binary prefixes divisible by five: maintain the remainder as the prefix shifts.
  • Paths in a matrix with sum divisible by k: the same remainder DP extended over a grid.

Whenever divisibility appears, the first move is to compress the sum into a remainder, and everything else is counting, shortest segments, pairing or extension to higher dimensions.

Java

public int maxSumDivThree(int[] nums) {
    int total = 0;
    final int INF = Integer.MAX_VALUE / 2;
    int one1 = INF, one2 = INF;
    int two1 = INF, two2 = INF;
    for (int x : nums) {
        total += x;
        if (x % 3 == 1) {
            if (x < one1) { one2 = one1; one1 = x; }
            else if (x < one2) { one2 = x; }
        } else if (x % 3 == 2) {
            if (x < two1) { two2 = two1; two1 = x; }
            else if (x < two2) { two2 = x; }
        }
    }
    int r = total % 3;
    if (r == 0) return total;
    long drop;
    if (r == 1) drop = Math.min(one1, (long) two1 + two2);
    else        drop = Math.min(two1, (long) one1 + one2);
    return drop >= INF ? 0 : total - (int) drop;
}

Two Java-specific traps: the sentinel must be half the maximum integer, since incrementing the maximum overflows; and a negative operand yields a negative remainder, so a floor-modulo is safer. Sums may also exceed a 32-bit integer, so widen where necessary.

Edges

  • A zero remainder returns the total immediately without consulting buckets.
  • A single element that is not divisible by three returns zero, the empty subset.
  • If neither candidate can be assembled, the answer is zero rather than a negative number.
  • Three ones and three twos both have remainder zero overall, so the whole array is taken.
  • An empty bucket means the corresponding candidate must be infinite rather than an out-of-range read.
  • Zero elements change no remainder.
  • Duplicates need no special handling; taking the smallest two after sorting is correct for them.

Common mistakes

  1. Reading the problem as choosing exactly three elements.
  2. Considering only the single-element discard and missing the two-element one.
  3. Returning zero from the helper when a bucket is too short, which invents a free discard.
  4. Taking the first two entries without sorting, or without maintaining the two smallest.
  5. Omitting the zero-remainder short circuit, which confuses the candidate arithmetic.
  6. Returning a negative value when no solution exists instead of zero.
  7. Updating the DP in place, which uses one element twice.
  8. Initialising the unreachable states to zero.
  9. Using the maximum integer as infinity in a fixed-width language.

How to answer it

Give the greedy with the reasoning about why only two shapes exist, since that argument is the discriminator. Then the DP as the sign-agnostic fallback, with the snapshot and the negative infinity noted. Then the generalisation: counting divisible subarrays, shortest removals, complementary pairing, and the grid extension.

Closing

The difficulty compresses into one conclusion: return the total if the remainder is zero, otherwise subtract the cheaper of one element with remainder r or two with the complement. Only two shapes are needed because in the world of remainders, same-kind pairs cancel and mixed pairs are wasted. Once that is clear the code is ten lines, and the rolling DP reminds you that when the positive precondition breaks, the machine that does not depend on it is the one to use.
