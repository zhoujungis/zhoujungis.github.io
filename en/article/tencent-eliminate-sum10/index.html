Eliminating adjacent pairs summing to ten: a stack, and a uniqueness proof

2026-08-31 · 13 min · Stack Frame

The problem

Given a string of digits from one to nine, two adjacent digits whose sum is ten may be removed, after which the two sides join and the check continues. What string remains?

5512  ->  the two fives cancel, leaving 12
1 + 2 is not 10, so the answer is 12

The one-line answer is a stack simulation. Three things separate good answers from adequate ones: why joining happens automatically with a stack, whether the order of eliminations matters, and whether the shortest remaining length is the same question.

Complements, and the stack

Within one to nine each digit has exactly one complement summing to ten, and five pairs with itself. Two consequences follow: the pairing is unique, which is the seed of the uniqueness argument later, and five plus five cancels, which is the case most often forgotten.

Instead of deleting a pair and rescanning, keep a stack representing the current string after reduction. A new digit only ever interacts with the top of the stack, which is the last remaining digit on the left. If they sum to ten, the top is popped and the new digit never enters; otherwise the new digit is pushed.

def eliminate(s: str) -> str:
    st = []
    for ch in s:
        if st and int(st[-1]) + int(ch) == 10:
            st.pop()
        else:
            st.append(ch)
    return "".join(st)

Two details are easy to get wrong. The stack from bottom to top is exactly the answer order, so joining gives the result with no reversal. And a conditional suffices rather than a loop, since one digit can cancel at most one top: after cancelling, the new digit is gone too and cannot pair with the revealed one.

Why the stack is correct

The simulation produces one result. If asked whether a different order changes it, saying you used a stack is not an answer; you need the result to be unique in the first place.

Termination is immediate: each step removes exactly two characters, so the length strictly decreases and the process stops within half the length.

Local confluence rests on the only critical pair, which is a digit with its complement on both sides. Removing the left pair leaves the single digit, and removing the right pair leaves the same single digit, so both orders agree. Pairs that do not overlap do not interfere.

By Newman's lemma, a terminating rewriting system that is locally confluent is globally confluent: from one string, any order of reductions ends at the same irreducible form. That is why the question can be posed without ambiguity.

So the final string is unique, and the shortest remaining length is just its length.

Measured, not asserted

Three checks were run. Exhaustively over all strings of length at most five on the digits one to nine, sixty-six thousand of them, four implementations, the stack, repeated rescans, leftmost-first and rightmost-first rescans, gave identical results. On two thousand random strings, leftmost, rightmost and random orders agreed. And the stack contents after every step equal the independent reduction of that prefix.

The negative example is worth volunteering: confluence is a property of these rules, not of reduction in general. Widen the rule so that sums of nine or ten both cancel on a sample string, and leftmost-first gives one digit while rightmost-first gives another. Same string, two results, and then a stack only produces some answer rather than the answer.

Shortest length is the same question

Each step removes two characters, so the number of cancellations is fully determined by the result length. And confluence means no sequence ends shorter, so that length is both a lower bound and achievable. Measured across five hundred random strings with six random orders each, none beat the stack.

Naive rescans versus the stack

The naive translation deletes all disjoint complementary pairs each round until no deletion occurs. Its weakness is adversarial input: a run of ones followed by a run of nines, where only the pair at the boundary can cancel, so each round scans from the start to the boundary and the whole thing is quadratic.

Doubling the length roughly quadruples the naive time, while the stack roughly doubles, so the gap widens to about two thousand times at eight thousand characters.

Three interesting readings at larger sizes: with all fives, the maximum stack depth is always one, since two fives cancel on sight; with random digits roughly one pair cancels per nine characters, which matches the one-in-nine complement probability; and yet the maximum depth on random input reaches about three quarters of the length, so the space really is linear in the worst case.

The rule varies, the skeleton does not: the stack is the reduced form of the string so far, and a new element only meets the top.

Follow-ups worth preparing. How many pairs cancelled: determined by the result length. List all possible final strings: there is only one, and with non-confluent rules it degenerates into a search. Can it be done without a stack: yes, recursively or by rescanning, at quadratic cost, or in place with an array and a cursor for constant space. Why the pairing table matters: the complement map is an involution without fixed points except five, which is exactly what makes the critical pair benign.

Java

public String eliminate(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (!st.isEmpty() && (st.peek() - '0') + (c - '0') == 10) {
            st.pop();
        } else {
            st.push(c);
        }
    }
    StringBuilder sb = new StringBuilder();
    while (!st.isEmpty()) sb.append(st.pollLast());
    return sb.toString();
}

Two Java traps: the deque pushes and pops at the top, so the output must be taken from the bottom, which is the opposite end; and building the stack out of string concatenation is quadratic, the same order as the naive rescan.

Edges and traps

  1. Reading the top of an empty stack, which happens on the first character.
  2. Counting only original adjacent pairs and missing the joins, which cancels one pair instead of two on a case like one, two, eight, nine.
  3. Using a loop instead of a conditional. It is unnecessary because one digit cancels at most one top, but you should be able to explain why.
  4. Rescanning each round, which is quadratic and two thousand times slower at eight thousand characters.
  5. Forgetting that five cancels with five.
  6. Answering only with the stack simulation and no argument for uniqueness, which loses marks on the follow-up about order.
  7. Not confirming the character set: a zero has complement ten, outside the allowed range, so it can never cancel.
  8. Outputting the stack top first, which reverses the answer.
  9. Confusing sum with difference; one and nine differ by eight and sum to ten, and the rule is the sum.

How to answer it

Give the complement observation, then the stack as the reduced form with new digits meeting only the top, and note that joining is automatic. Then the uniqueness argument, which is the discriminator: termination, the single critical pair, Newman's lemma, hence one result and hence the shortest length. Offer the counterexample with a widened rule to show confluence comes from the problem, not in general. Then the complexity comparison and the family.

One line: the stack holds the reduced form, a new digit meets only the top, and greedy is safe because the system is confluent.

Closing

Anyone can reduce a four-character string by hand. Three sentences make the answer complete: the stack is the reduced form, so joining needs no string surgery; two digits cancel exactly when they are complements, with five pairing with itself; and the system is confluent, so the result is unique. The measurements merely nail the third sentence to data: three and a half seconds against one point seven milliseconds at eight thousand characters.
