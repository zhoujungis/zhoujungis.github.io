LC 1928, cheapest path within a time budget: a layered graph

2026-10-14 · 16 min · Stack Frame

The problem

Cities are joined by undirected edges carrying a travel time but no cost. Every time you pass through a city you pay its toll, including the first and the last. Find the cheapest route from zero to the last city within a total time budget, or minus one.

edges        [[0,1,10],[1,2,10],[2,5,10],[0,3,1],[3,4,10],[4,5,15]]
passingFees  [5,1,2,20,20,3]

maxTime 30 -> 11   (0-1-2-5, time 30, tolls 5+1+2+3)
maxTime 29 -> 48   (0-3-4-5, time 26, tolls 5+20+20+3)
maxTime 25 -> -1

It looks like a shortest path, and the real threshold is counterintuitive: there are two routes, one costing eleven and one costing forty-eight, and the difference is not which is cheaper but which arrives in time. One minute of budget changes the answer completely. That jump is the whole point of this article: why a one-dimensional state must be wrong, and how a layered graph repairs it.

Definition and transition

The tempting wrong version runs a shortest path where the cost is the arrival city's toll. It is wrong for a concrete reason: the cheapest route takes thirty minutes and is simply not allowed when the budget is twenty-nine. The one-dimensional state discarded the arrival time and therefore mistook an overtime cheap route for the answer.

The fix is to put time into the state: not the cheapest way to reach a city, but the cheapest way to reach it at a specific moment.

dp[t][v] = the cheapest toll total for arriving at city v exactly at time t
dp[0][0] = passingFees[0]
dp[t + et][u] = min(dp[t + et][u], dp[t][v] + passingFees[u])
answer   = min over t <= maxTime of dp[t][n-1]

def minCost(maxTime, edges, passingFees):
    n = len(passingFees)
    INF = float("inf")
    dp = [[INF] * n for _ in range(maxTime + 1)]
    dp[0][0] = passingFees[0]
    for t in range(maxTime + 1):
        for x, y, et in edges:
            arr = t + et
            if arr > maxTime:
                continue
            if dp[t][x] < INF:
                dp[arr][y] = min(dp[arr][y], dp[t][x] + passingFees[y])
            if dp[t][y] < INF:
                dp[arr][x] = min(dp[arr][x], dp[t][y] + passingFees[x])
    ans = min(dp[t][n - 1] for t in range(maxTime + 1))
    return -1 if ans == INF else ans

Three details decide it. The base case pays the start city's toll, since passing through includes standing on it. Only reachable cells are relaxed, which is both the meaning of spreading outward layer by layer and a guard against adding to infinity. And any transition arriving late is dropped, because time only moves forward.

One more thing is easy to miss: the answer is the minimum over all times, not the final row. Arriving early and arriving late are separate cells, and earlier is not necessarily cheaper.

Why the clock must be a state

The one-dimensional state collapses two genuinely different facts into a single number: the cheap route costing eleven over thirty minutes, and the expensive route costing forty-eight over twenty-six. Keeping only the fare records the first and forgets that it is overtime. Cost and time are not interchangeable, and neither dominates the other, so both must survive into the state.

layer t holds one copy of every city:
  point = (t, v)      edge = (x, y, time)
  dp[t][v] = shortest cost to reach the point (t, v)

The budget is simply the layer cap, so a path problem with a time window is a shortest path on a graph with a bounded number of layers.

Note also that arriving later can be more expensive, since every step pays the destination's toll, so detouring is not free. Taking the minimum over all times handles that without assuming anything about early versus late.

The final answer is the minimum over the goal column, which lands on the expensive but fast route. The later arrival costs seventy-one, which is exactly why the minimum must span all times. Following predecessors backwards from that cell recovers the city sequence through the expensive route.

The unconstrained cheapest route is necessarily no more expensive than the constrained one, since ignoring the window only enlarges the search space. Being cheap and being in time are simply different things.

The family

  • Cheapest flight within k stops: the state is the number of stops used and the city, which is word-for-word the same structure with stops replacing time and airfare replacing tolls.
  • Network delay time: a single-source shortest path with no window at all, answering the latest arrival.
  • Path with minimum effort: the aggregation changes from a sum to a maximum along the path.
  • Most probable path: products instead of sums, maximised instead of minimised.
  • Number of ways to arrive: the same layered graph with addition instead of minimum.

Layers are time, stops or steps; points are cities or states; edge weights may be durations, fares or height differences; the aggregation may be minimum, maximum, product or count; and the window is the layer cap.

Java

public int minCost(int maxTime, int[][] edges, int[] passingFees) {
    int n = passingFees.length;
    final int INF = Integer.MAX_VALUE / 2;
    int[][] dp = new int[maxTime + 1][n];
    for (int[] row : dp) Arrays.fill(row, INF);
    dp[0][0] = passingFees[0];
    for (int t = 0; t <= maxTime; t++) {
        for (int[] e : edges) {
            int x = e[0], y = e[1], et = e[2];
            int arr = t + et;
            if (arr > maxTime) continue;
            if (dp[t][x] < INF) dp[arr][y] = Math.min(dp[arr][y], dp[t][x] + passingFees[y]);
            if (dp[t][y] < INF) dp[arr][x] = Math.min(dp[arr][x], dp[t][y] + passingFees[x]);
        }
    }
    int ans = INF;
    for (int t = 0; t <= maxTime; t++) ans = Math.min(ans, dp[t][n - 1]);
    return ans >= INF ? -1 : ans;
}

A priority-queue search over states of cost, elapsed time and city is equivalent, and it can terminate as soon as the goal is popped, since the first pop carries the minimum. Adding a predecessor table lets the path itself be reconstructed.

Edges

  • Unreachable means minus one, not the most expensive route; the window is a hard constraint rather than a penalty.
  • A budget smaller than the fastest route's duration always gives minus one.
  • A budget larger than any possible duration degenerates to a plain cost shortest path, where the one-dimensional version happens to be correct.
  • The start and the end both pay their own tolls, one in the base case and one in each relaxation.
  • Edges are undirected, so both directions must be relaxed; adding one is the most common silent error.
  • Parallel edges are allowed, and the shortest duration between a pair is the one that matters.
  • Self loops are excluded, so every step strictly advances time and no zero-cost same-layer moves exist.
  • With two cities the answer is just the two tolls, provided the single edge fits the budget.
  • Tolls are positive, so detouring always costs more and the greedy search is valid.

The whole table is needed because edges have different durations, so an update can land on any future layer and a single row cannot be kept. Within the stated constraints the total work is on the order of a million operations.

Common mistakes

  1. Using the one-dimensional state, which mistakes the overtime cheap route for the answer. The headline trap of this problem, and one minute of budget exposes it.
  2. Reading the answer from the last row, since arriving at the budget is not required and a later arrival can be more expensive.
  3. Forgetting that the start and the end pay their tolls.
  4. Relaxing from unreachable cells, which adds to infinity and can overflow.
  5. Not pruning transitions that arrive late.
  6. Adding only one direction for undirected edges.
  7. Using the maximum integer as infinity, which overflows on the first addition.
  8. Assuming early arrival is always cheaper, which the table contradicts.
  9. Keeping the parallel edge with the largest duration instead of the smallest.

How to answer it

Define the state, the base, the transition and the answer, and explain up front why two dimensions are necessary: time cannot be compressed into cost, and the cheaper route may be overtime. Then the three guards, which decide correctness more than speed: only relax from reached cells, drop late transitions, and charge both the start and the end. Then the equivalent priority-queue formulation over cost, elapsed time and city, which terminates when the goal is popped, and note that it is the same machine as the k-stops flight problem.

Closing

The difficulty compresses into one counterintuitive fact: time cannot be compressed. Folding the clock into the state spreads the problem into a layered graph, after which everything is ordinary layer-by-layer relaxation. Two reminders remain: both endpoints pay, and the answer is a minimum over all times, because arriving later may cost more.

From the first cell outward to the best arrival, then back along predecessors to the start, is the whole of path planning with a deadline.
