LC 72, edit distance: prefix against prefix, and the rolling row

2026-09-15 · 15 min · Stack Frame

The problem

Return the minimum number of insertions, deletions and substitutions needed to turn one word into another.

horse -> ros
horse -> rorse   (substitute h for r)
rorse -> rose    (delete r)
rose  -> ros     (delete e)
-> 3

Two anchors: prefix against prefix

The previous article's anchor was the ending index. This problem needs two anchors at once: the state is the minimum cost of turning the first i characters of one string into the first j characters of the other.

Why prefixes rather than endings: edit operations insert and delete at arbitrary positions, so the last step cares not about which character ends the string but about how much of each remains. Only a pair of prefix lengths fully describes the work still to do, which is the fork between single-sequence and two-sequence problems.

With both anchors placed, the transition only needs to consider the final pair of characters, since everything before is absorbed into the table.

The initialisation is not zero. Turning an empty string into j characters costs j insertions, and turning i characters into nothing costs i deletions. The first row and column are not filler, they are the semantics, and filling them with zero breaks the official sample outright.

Three operations, three neighbours

Last operationMeaningRemaining workCost
SubstituteChange the current character of one into the otherPrefixes one shorter on both sidesThe diagonal plus one
DeleteRemove a character from the first stringFirst prefix one shorter, second unchangedThe cell above plus one
InsertAdd a character to the first stringFirst prefix unchanged, second one shorterThe cell to the left plus one
 
def minDistance(word1: str, word2: str) -> int:
    m, n = len(word1), len(word2)
    a, b = list(word1), list(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for j in range(n + 1):
        dp[0][j] = j
    for i in range(1, m + 1):
        dp[i][0] = i
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i - 1][j - 1], dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]

A compact form merges the branch: the diagonal plus one if the characters differ, then the minimum with the two neighbours plus one.

One fact worth stating: swapping the labels of insertion and deletion changes no number, since the minimum is over the same set of neighbours. It only matters when the operation sequence must be printed, because the labels decide the reconstruction. Harmless numerically, fatal for reconstruction, which is the common trap of every symmetric transition.

Four cells deserve attention. The first shows substitution beating the alternatives, so a matching rule that only permits insert and delete would cost two here. The second is a free diagonal copy on equal characters. The third shows a boundary cell participating in a real transition, which is why the first column must be correct. And the last cell's minimum happens to be the cell above, which is the clue for both the compression and the bug in it.

Compressing to one row

Each entry depends only on the previous row and its left neighbour in the current row, so earlier rows can be discarded.

NeighbourWhere it livesSurvives
AboveThe buffer slot before it is writtenYes, just in time
LeftThe previous slot, already writtenYes, same row
DiagonalThe previous slot's old valueNo, already overwritten
 
def minDistance(word1: str, word2: str) -> int:
    m, n = len(word1), len(word2)
    a, b = list(word1), list(word2)
    buf = list(range(n + 1))
    for i in range(1, m + 1):
        prev = buf[0]
        buf[0] = i
        for j in range(1, n + 1):
            tmp = buf[j]
            if a[i - 1] == b[j - 1]:
                buf[j] = prev
            else:
                buf[j] = 1 + min(prev, buf[j], buf[j - 1])
            prev = tmp
    return buf[n]

Two save-before-write positions matter: the row start and each cell. The instant before an overwrite is the only chance to read the old value.

Swapping so the shorter string is the column gives space proportional to the shorter length, which is legal because edit distance is symmetric.

Java

public int minDistance(String word1, String word2) {
    char[] a = word1.toCharArray();
    char[] b = word2.toCharArray();
    int m = a.length, n = b.length;
    int[] buf = new int[n + 1];
    for (int j = 0; j <= n; j++) buf[j] = j;
    for (int i = 1; i <= m; i++) {
        int prev = buf[0];
        buf[0] = i;
        for (int j = 1; j <= n; j++) {
            int tmp = buf[j];
            if (a[i - 1] == b[j - 1]) {
                buf[j] = prev;
            } else {
                buf[j] = 1 + Math.min(prev, Math.min(buf[j], buf[j - 1]));
            }
            prev = tmp;
        }
    }
    return buf[n];
}

Write the two-dimensional version first and then convert live, since the transition is identical and the audience can see why the diagonal is recoverable.

Edges

  • One empty string answers the other's length, which the rolling version handles because the inner loop never runs.
  • Identical strings answer zero, and every cell takes the free branch.
  • Single characters show substitution, deletion and insertion each costing one.
  • The distance is symmetric, which is the basis for choosing the shorter column.
  • Non-BMP characters must be split by code point, or one emoji counts as two characters.

Printing the operations needs the full table or a divide-and-conquer scheme that trades time for space, and saying that the value and the path have different storage needs is worth a note.

Common mistakes

  1. Scanning the inner loop backwards out of knapsack habit, which reads the previous row where the current row is needed. The official sample still returns three, because the winning neighbour is precisely the one that remains correct under a backwards scan. A three-character identity case exposes it immediately.
  2. Charging for equal characters, which makes even identical strings cost something.
  3. Filling the boundary row or column with zeroes instead of the semantic values.
  4. Omitting substitution, which turns the problem into insert-and-delete only.
  5. Updating the saved diagonal at the wrong moment, which turns the current cell's fresh value into the next cell's diagonal.
  6. Expecting a single row to reconstruct the operation sequence.

How to answer it

Place both anchors and justify prefixes. Map the three operations onto the three neighbours. State the symmetry between insert and delete and its consequence for reconstruction. Then the compression: only the diagonal is destroyed by your own write, so one scalar suffices, plus one save at each row start. Then the counterexample to the backwards scan and why the sample hides it. Then the variants: deletions only, longest common subsequence as the same table with different bookkeeping, and reconstruction from the full table.

Closing

The first question tests whether you dare place two anchors, prefix against prefix, after which the recurrence writes itself. The second tests whether you know which of the three dependencies is fragile. Both moves are the same as before: pin the state down, then optimise. And the real trap is never in the recurrence but in the order of iteration, where the official sample happens to place the minimum on the only neighbour a backwards scan leaves intact.
