How to Deploy a Django Backend to PythonAnywhere

2026-07-03 · 7 min · Stack Frame

🎯 Introduction

This tutorial walks through deploying a Django REST Framework backend to PythonAnywhere, step by step.
PythonAnywhere's free plan supports Python web app hosting, has native Django support, and requires no server administration — a great fit for personal projects.

What Do You Need Before You Start?

GitHub account To hold the code
PythonAnywhere account The free plan is enough — sign up here
Django project A complete project that runs locally

📂 Step 1: Prepare the Project

1.1 Confirm the project structure

A standard Django project should look something like this: 
backend/
├── blog_api/              # Django project config
│   ├── settings.py        # Core settings file
│   ├── urls.py            # Root URLconf
│   └── wsgi.py            # WSGI entry point
├── articles/              # Your app
│   ├── models.py
│   ├── views.py
│   └── serializers.py
├── manage.py
├── requirements.txt       # Python dependency list
└── venv/                  # Local virtualenv

1.2 Generate requirements.txt

cd backend
source venv/bin/activate    # Linux/Mac
# venvScriptsactivate     # Windows

# Freeze every current dependency
pip freeze > requirements.txt

# Confirm the file contains these key packages
cat requirements.txt | grep -E "django|rest_framework|simplejwt|corsheaders"

1.3 Production settings

Edit backend/blog_api/settings.py so configuration is read from environment variables: 
import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

# ✅ Read from the environment, with a fallback default
SECRET_KEY = os.environ.get(
    'DJANGO_SECRET_KEY',
    'django-insecure-dev-key-change-me'
)

DEBUG = os.environ.get('DEBUG', 'True') == 'True'

ALLOWED_HOSTS = os.environ.get('ALLOWED_HOSTS', '*').split(',')

# ✅ CORS: pin explicit origins in production
_cors = os.environ.get('CORS_ALLOWED_ORIGINS', '')
if _cors:
    CORS_ALLOWED_ORIGINS = [o.strip() for o in _cors.split(',') if o.strip()]
    CORS_ALLOW_ALL_ORIGINS = False
else:
    CORS_ALLOW_ALL_ORIGINS = True  # Allow every origin in development

# ✅ Static files
STATIC_URL = 'static/'
STATIC_ROOT = BASE_DIR / 'staticfiles'

# ✅ Media files
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'

1.4 Push the code to GitHub

git add backend/
git commit -m "chore: production-ready Django config"
git push origin master

2.1 Open the Bash console

Log in to pythonanywhere.com → Dashboard → click Bash:

2.2 Clone the code

# Clone your repository
git clone https://github.com/YOUR_USERNAME/YOUR_REPO.git
cd YOUR_REPO/backend

# Make sure the files are all there
ls -la

🐍 Step 3: Create a Virtualenv

3.1 Create the venv

# PythonAnywhere supports Python 3.10 / 3.11 / 3.12
python3.12 -m venv venv

# Activate the virtualenv
source venv/bin/activate

# You'll see a (venv) prefix appear in front of your prompt

3.2 Install dependencies

pip install -r requirements.txt
⚠️ If the install fails, check whether requirements.txt pulls in an incompatible package. You can start by installing the core packages by hand: bash pip install django djangorestframework djangorestframework-simplejwt django-cors-headers

3.3 Generate a production secret key

python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
📋 Copy the generated key and keep it somewhere safe — you'll need it in the next step!

4.3 Configure the WSGI file

Click the blue WSGI configuration file link and replace the entire contents with: 
import os
import sys

# Set the project path
path = '/home/YOUR_USERNAME/YOUR_REPO/backend'
if path not in sys.path:
    sys.path.insert(0, path)

# Set environment variables (swap in the key you generated in step 4!)
os.environ['DJANGO_SETTINGS_MODULE'] = 'blog_api.settings'
os.environ['DJANGO_SECRET_KEY'] = 'your-production-secret-key'
os.environ['DEBUG'] = 'False'
os.environ['ALLOWED_HOSTS'] = 'yourusername.pythonanywhere.com'
os.environ['CORS_ALLOWED_ORIGINS'] = 'https://yourusername.github.io'

from django.core.wsgi import get_wsgi_application
application = get_wsgi_application()
⚠️ Replace YOUR_USERNAME and YOUR_REPO with your own values!
Save the file and close the editor.

🗄️ Step 5: Initialize the Database

5.1 Run migrations

Back in the Bash terminal: 
cd ~/YOUR_REPO/backend
source venv/bin/activate

# Run every database migration
python manage.py migrate

# You should see output like this:
# Operations to perform:
#   Apply all migrations: articles, comments, ...
# Running migrations:
#   Applying articles.0001_initial... OK
#   ...

5.2 Create an admin account

python manage.py createsuperuser
Answer the prompts: 
Username: admin
Email address: your@email.com
Password: ********
Password (again): ********
Superuser created successfully.

5.3 Collect static files

python manage.py collectstatic --noinput

# Output: 157 static files copied to 'staticfiles'

What Are the Common Pitfalls?

Q1: The site shows "Something went wrong"

Check the error log: Web → Error log, then work backwards from the specific error.
Common causes: - Wrong path in the WSGI file - Dependencies not installed in the virtualenv - Secret key not set

Q2: Migration errors

Make sure the virtualenv is active: source venv/bin/activate

Q3: Static files return 404

Check the Static Files mapping — the URL and Directory have to match exactly.

Q4: CORS errors (browser console)

Check that CORS_ALLOWED_ORIGINS in the WSGI file includes your frontend's domain.

Q5: Code changes don't take effect

You must click Reload after every code change! 
# The standard workflow for updating the code:
cd ~/YOUR_REPO/backend
git pull                      # Pull the latest code
source venv/bin/activate
pip install -r requirements.txt  # Install new dependencies (if any)
python manage.py migrate  # Run new migrations (if any)
python manage.py collectstatic --noinput
# Then go to the Web page and hit Reload
