LC 704 and 69: binary search on an array, binary search on the answer

2026-09-25 · 14 min · Stack Frame

The problems

704: search a sorted array for a target and return its index, or minus one, in logarithmic time.

[-1,0,3,5,9,12], target 9  ->  4
[-1,0,3,5,9,12], target 2  ->  -1

69: return the integer part of the square root of a non-negative integer.

x = 8   ->  2     (2.828 truncated)
x = 16  ->  4

These are the textbook and the graduation exam. The first searches a real array for a value. In the second no array exists: the sorted domain is an integer interval you invent, and the thing being sought is not a value but a predicate boundary.

704: binary search is invariant maintenance

Most people remember the midpoint comparison, which is the surface. The essence is an invariant: if the target is present, its index always lies inside the closed interval.

Each probe has three outcomes. Equality closes the case. A smaller midpoint value eliminates that index and everything left of it, since the array is sorted. A larger one eliminates that index and everything right of it. Each round discards half and never violates the invariant, because the discarded half cannot contain the answer. When the interval empties, the contrapositive gives the answer directly.

So there are three rules, and all of them follow from the closed-interval convention. Mixing conventions is the root of most binary search bugs.

def search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + ((right - left) >> 1)
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

The loop condition matches an empty closed interval, which is exactly left exceeding right. The midpoint is computed as left plus half the span, which avoids overflow in fixed-width integer languages. And the bounds move past the midpoint because that index has already been examined.

Reframe it in your head: you are not halving an array, you are discarding half the suspects each round without ever discarding the culprit.

69: the answer is a predicate boundary

There is no array, but there is a predicate: k squared is at most x, over the integer interval from zero to x. The predicate is monotone, true then false, and the integer part of the root is exactly the last true index.

def mySqrt(x):
    lo, hi, ans = 0, x, 0
    while lo <= hi:
        mid = lo + ((hi - lo) >> 1)
        if mid * mid <= x:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans

There is a free property at the end: the answer equals both the low bound minus one and the high bound, since the high pointer comes to rest on the last true value. That is the red-blue boundary view: the low pointer is the first false, the high pointer is the last true, and the answer lives in the crack between them.

Binary searching the answer space is the real lesson. The answer need not live in an existing array; construct a monotone predicate and the range of possible values becomes your array. Banana eating, package shipping within a day limit, and the first bad version are all this sentence wearing different clothes.

Newton iteration is the other road: repeatedly set k to the average of k and x over k, which converges quadratically. For eight it goes eight, four, three, two. Theoretically faster, and fewer than one candidate in ten writes it, partly because proving that the integer variant lands on the floor rather than the ceiling takes extra argument. The binary version wins because every step follows the discipline above.

Probes two and three are the fingerprint: the predicate holds and the search does not stop. That is the difference between seeking a boundary and seeking a value.

The family

  • Search insert position. Delete the return on a hit and return the low bound afterwards, which on a miss is the first element at least as large as the target.
  • First and last position of an element. Two boundary searches, one for at least and one for at most.
  • Smallest letter greater than the target. The same predicate with a different comparison.
  • First bad version, guess number. The canonical demonstrations of searching the answer space, with the predicate supplied by the system.
  • Minimum eating speed, ship within days. Answer search with an inner simulation computing the predicate, which is only usable once monotonicity is established.
  • Valid perfect square. The same shape as the root problem, asking for exactness instead of a floor.
  • Find peak, minimum in a rotated array. Binary search without a total order, where the midpoint's relation to its neighbours still tells you which half contains the answer.
  • Search a 2D matrix. A staircase search from the top right, eliminating a row or a column per step.

One way to see the lineage: 704 is learning the alphabet, the insert and range problems are writing sentences, the answer-search problems are essays, and the peak and rotation problems are reading comprehension.

Java

public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + ((right - left) >> 1);
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}

public int mySqrt(int x) {
    int lo = 0, hi = x, ans = 0;
    while (lo <= hi) {
        int mid = lo + ((hi - lo) >> 1);
        if ((long) mid * mid <= x) {
            ans = mid;
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return ans;
}

Widening to a long before multiplying is the standard fix. The alternative is dividing instead, which is equivalent under integer division but needs a guard for a zero midpoint.

Edges

For the search: an empty array leaves the loop unentered and returns minus one naturally; a single element works whether it matches or not; a target smaller or larger than everything shrinks from one side for the full logarithmic number of probes. Duplicates are excluded by the problem, and this template returns whichever match it happens to hit rather than the leftmost, which is a different problem.

For the root: zero and one return themselves; the maximum 32-bit input is the classic overflow minefield, where the answer changes by one exactly across the boundary; and for x at least two the high bound can start at half the value plus one, saving a probe.

Common mistakes

  1. Using a strict loop condition with a closed interval, which skips the single-element case.
  2. Moving a bound to the midpoint without stepping past it, which stops shrinking and loops forever.
  3. Adding both bounds before halving, which overflows in fixed-width languages.
  4. Squaring the midpoint in the root problem without widening, which turns the value negative and inverts the predicate.
  5. Forgetting to prove monotonicity before copying the template; halving is only valid on a predicate that is true then false.
  6. Calling the language square root function, which is safe for small inputs and exactly what the question is not asking for.
  7. Counting iterations in Newton instead of testing the square, since the integer iteration may overshoot by one.

How to answer it

For the search, state the invariant, then the three rules tied to the closed interval, then the return value when the interval empties, noting that the low bound is the insertion point. For the root, construct the predicate, show that the answer is its last true value, and contrast the single behavioural difference from the previous template. Then the overflow countermeasures, and Newton as a bonus. If asked why the loop condition is inclusive, derive it on the spot: a single-element closed interval still contains one unchecked element, which an exclusive condition would skip.

Closing

This pair reduces binary search from a trick to a discipline: one invariant, one convention, three rules. One teaches stopping on a hit; the other teaches not stopping on a hit, because the thing sought was never an element but the line between true and false. Once that boundary is firm, the rest of the family is the same sentence repeated.
