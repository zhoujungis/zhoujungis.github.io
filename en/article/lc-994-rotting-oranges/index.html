LC 994, rotting oranges: multi-source BFS and a table of rot times

2026-10-12 · 13 min · Stack Frame

The problem

A grid holds empty cells, fresh oranges and rotten oranges. Every minute, every rotten orange rots its four orthogonal fresh neighbours. Return the fewest minutes until no fresh orange remains, or minus one if impossible.

2 1 1
1 1 0     -> 4
0 1 1

2 1 1
0 1 1     -> -1   (the isolated fresh orange never rots)
1 0 1

Three details to pin down: empty cells do not propagate, since rot only spreads onto fresh oranges; the spread is simultaneous across all rotten oranges each minute, not sequential; and a grid with no fresh oranges at all answers zero.

The skeleton in one sentence: all rotten oranges start a breadth-first search simultaneously and expand outward in rings, one layer per minute, and the number of layers is the answer.

The mental switch compared with ordinary search is that every rotten orange enters the queue at the start as layer zero, and the first-visit property of breadth-first search automatically computes each cell's distance to the nearest source, so the rot time is that distance and the answer is the maximum.

The code

from collections import deque

def orangesRotting(grid):
    m, n = len(grid), len(grid[0])
    q = deque()
    fresh = 0
    for r in range(m):
        for c in range(n):
            if grid[r][c] == 2:
                q.append((r, c))
            elif grid[r][c] == 1:
                fresh += 1
    minute = 0
    while q and fresh:
        for _ in range(len(q)):
            r, c = q.popleft()
            for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
                if 0 <= nr < m and 0 <= nc < n and grid[nr][nc] == 1:
                    grid[nr][nc] = 2
                    fresh -= 1
                    q.append((nr, nc))
        minute += 1
    return minute if fresh == 0 else -1

Three details decide it. All rotten oranges enter the queue initially, since starting with one is the biggest trap here: other sources begin several minutes late and the answer inflates or goes wrong. The layer length is captured before the loop so that newly enqueued cells belong to the next minute. And marking at enqueue time, together with the fresh counter, prevents a cell from being enqueued by several neighbours and gives the condition for minus one.

Three ways to count minutes

The layered loop above increments a counter after each layer. The timestamp variant stores the time with each cell and pushes time plus one into the answer when enqueuing, and its trap is that the update must happen at enqueue: if it happens at dequeue, the early exit leaves the final batch uncounted and the answer is short by one.

The distance-field variant stamps each cell the first time it is visited, so the table itself becomes the answer, with the maximum stamp being the rot time. An empty grid is handled by defaulting the maximum to zero.

Why count fresh oranges

Two reasons. The loop condition stops as soon as the count reaches zero, avoiding pointless work on a trailing layer. And the failure condition is that the count is still positive when the search ends, meaning some fresh orange is walled off.

Note the correct failure test is the count, not an empty queue. An empty queue with a zero count is normal completion, and an empty queue with a positive count is failure.

Java

class Solution {
    private static final int[][] DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    public int orangesRotting(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int fresh = 0, minute = 0;
        Deque<int[]> queue = new ArrayDeque<>();
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (grid[r][c] == 2) queue.offer(new int[]{r, c});
                else if (grid[r][c] == 1) fresh++;
            }
        }
        while (!queue.isEmpty() && fresh > 0) {
            for (int size = queue.size(); size > 0; size--) {
                int[] cur = queue.poll();
                for (int[] d : DIRS) {
                    int nr = cur[0] + d[0], nc = cur[1] + d[1];
                    if (nr < 0 || nr >= m || nc < 0 || nc >= n || grid[nr][nc] != 1) continue;
                    grid[nr][nc] = 2;
                    fresh--;
                    queue.offer(new int[]{nr, nc});
                }
            }
            minute++;
        }
        return fresh == 0 ? minute : -1;
    }
}

The size must be captured before the loop, or the next layer gets counted into this one. And if the input must not be modified, replace the in-place marking with a visited array.

The family

  • Nearest zero in a matrix: zeros are the sources, the same distance field.
  • Shortest path in a binary matrix: single source to single target, the opposite shape.
  • Map analysis: the water cell farthest from land, which is the same maximum after a multi-source search.
  • Shortest bridge: colour the first island depth-first, then search from all of its cells.
  • Highest point on a map: water is the source and heights grow outward.
  • Walls and gates: fill each room with its distance to the nearest gate.

The template is always the same: enqueue all sources, advance by layers, visit each cell once. What varies is who the sources are and what is taken at the end.

Edges

  • No fresh oranges answers zero, since the loop never runs.
  • No rotten oranges with fresh ones answers minus one.
  • An entirely empty grid answers zero.
  • Sources and fresh oranges separated by empties answer minus one.
  • A single cell answers zero unless it is fresh, which answers minus one.
  • A corridor answers the distance of the farthest fresh orange.
  • Several sources meeting in the middle need no special handling, since first arrival is nearest.

Complexity

Linear in the number of cells for all three variants, since each cell is enqueued once and each adjacency checked once. Space is linear, because a single layer can fill the grid when everything is connected.

Common mistakes

  1. Enqueueing only the first rotten orange, which degenerates to a single source and inflates the answer.
  2. Counting minutes per cell rather than per layer.
  3. Marking on dequeue, which lets several neighbours enqueue the same cell and decrements the fresh count repeatedly.
  4. Testing failure by an empty queue, which misclassifies a normal finish with a trailing layer.
  5. Spinning one extra round after the fresh count reaches zero.
  6. Treating empty cells as propagators, when they are walls.
  7. Updating timestamps at dequeue rather than enqueue, which loses the final batch.
  8. Starting the minute counter at one, so an already-rotten grid answers one instead of zero.
  9. Reusing the grid after modifying it in place.
  10. Writing the spread as sequential rather than simultaneous, which flattens a minute into several and understates the answer.

How to answer it

Give the skeleton, then two justifications, which are where candidates separate: why multiple sources in one search rather than one search per source, which is linear against multiplicative and requires no per-cell minimum because first arrival is nearest; and why not depth-first, since rot times are shortest times and depth-first wanders.

Then the variants across sources, targets and dimensions, and the weighted extension where differing rot speeds require a priority queue instead.

Closing

The difficulty compresses into the word multiple: several sources, so all of them enter the queue at once; time advances by minutes, so layers must be cut; and the answer is either a layer count or a maximum timestamp. Twenty lines of code, with an entire family of grid distance-field problems standing behind it, all the same machine with a different source.
