LC 124, maximum path sum: the return value only takes one arm

2026-09-23 · 17 min · Stack Frame

The problem

A path is a sequence of nodes where consecutive ones are connected by an edge, no node appears twice, and at least one node is present. It need not pass through the root. Return the maximum sum over all paths.

[-10,9,20,null,null,15,7] -> 42    (15 + 20 + 7)
[1,2,3]                   -> 6     (2 + 1 + 3)
[-3]                      -> -3

This is the watershed of tree DP. It is not solved by adding a few more conditions; it requires understanding one thing, and the table below maps each requirement to a line in the statement.

Why the obvious approach is not enough

def maxPathSum(self, root):
    best = -float('inf')

    def all_paths_from(node):
        if not node:
            return [0]
        lefts = all_paths_from(node.left)
        rights = all_paths_from(node.right)
        return [node.val + x for x in lefts] + [node.val + x for x in rights]

    def dfs(node):
        nonlocal best
        if not node:
            return
        for a in [0] + all_paths_from(node.left):
            for b in [0] + all_paths_from(node.right):
                best = max(best, node.val + a + b)
        dfs(node.left)
        dfs(node.right)

    dfs(root)
    return best

Enumerating every path is correct and re-walks subtrees repeatedly, which is quadratic or worse and times out at thirty thousand nodes. What it fails to notice is that the needed information is a single number per subtree, and that is where post-order DP enters.

The shape of a path

straight                     arch
   *                        *
   |                       / \
   *                      *   *
   |                      |   |
   *                      *   *

Because no node repeats, a path in a binary tree has exactly one of these two shapes, and every path has a unique highest node: its endpoint if it is straight, its bend if it is an arch.

So the problem becomes computing, for each node, the best path that peaks there, and taking the maximum. A peak path decomposes into the node value plus the best downward straight chain from each side.

Note the distinction: what comes from a subtree must be a downward chain rooted at that subtree, not the best path inside it. The best path inside a subtree may itself be an arch, and an arch cannot be attached to a parent, because attaching it turns the result into a fork.

def gain(node):
    if not node:
        return 0
    return node.val + max(gain(node.left), gain(node.right))

That computes the contribution in linear time, bottom up.

The one real difficulty: two quantities

def gain(node):
    if not node:
        return 0
    left  = max(gain(node.left),  0)
    right = max(gain(node.right), 0)

    best = max(best, node.val + left + right)

    return node.val + max(left, right)

Return valueA straight chain, one armHanded to the parent to extendvalue plus the larger side

The question an interviewer will ask is why the return value is not the full sum. The answer is that a path cannot bend twice.

Suppose the twenty returned forty-two using both arms. Its parent minus ten would take that and bend again into minus ten plus forty-two, but the path through the twenty already bent once, and attaching it upward makes the whole thing a fork in which the twenty appears twice, once on the way to fifteen and once on the way to seven. That violates the rule that no node repeats.

two bends, not a path          one bend, a path
      -10                           -10
     /                             /
    20                           20
   /                            /
 15    7                        7

So the upward report keeps one arm in reserve, while the answer candidate spends both because it ends at this node and will never be extended.

One sentence: the return takes an edge, the answer takes a peak.

The zero in max(gain, 0) is the optimisation

People often read that zero as a null guard. It is a decision: if an arm sums negative, attaching it only lowers the total, so better not to attach it.

    1
   / \
 -5   3

Without clipping the peak is one minus five plus three, which is minus one. With clipping it is one plus zero plus three, which is four. The five reports minus five, the maximum with zero is zero, and the meaning is "do not come this way".

So the clipping is not optional insurance; it is half the algorithm, of equal weight with updating the best.

Why the best starts at negative infinity

Because a path contains at least one node, and a zero initial value corresponds to the empty path, which is not legal. A single node holding minus three must return minus three, not zero. Trees that are entirely negative expose this immediately.

That is why the two quantities cannot be validated by running the sample; they have to be understood.

The code

class Solution:
    def maxPathSum(self, root: TreeNode) -> int:
        self.best = -float('inf')

        def gain(node: TreeNode) -> int:
            if not node:
                return 0
            left  = max(gain(node.left),  0)
            right = max(gain(node.right), 0)

            self.best = max(self.best, node.val + left + right)

            return node.val + max(left, right)

        gain(root)
        return self.best

The initial value cannot be zero, for the reason above. The two zeros are the clipping decision, and the base case already handles an empty subtree so no extra guard is needed. The peak candidate only updates the answer and is never returned; the return takes the fatter arm.

The order matters: update the answer before returning, because the peak quantity exists only at this node and is lost once the call returns.

Time is linear, one visit per node. Space is the tree height, linear in the degenerate case.

class Solution:
    def diameterOfBinaryTree(self, root: TreeNode) -> int:
        self.best = 0

        def depth(node: TreeNode) -> int:
            if not node:
                return 0
            left  = depth(node.left)
            right = depth(node.right)

            self.best = max(self.best, left + right)

            return 1 + max(left, right)

        depth(root)
        return self.best

The absence of clipping here is proof that the zero in the previous problem exists because values can be negative, rather than being a general pattern. The initial best also differs: negative infinity there, zero here, because a diameter cannot be less than zero.

If an interviewer gives you both, say the skeleton is identical and the difference is nodes versus edges, and that the second needs no clipping. That sentence demonstrates understanding rather than recall.

Variant two: longest univalue path

class Solution:
    def longestUnivaluePath(self, root: TreeNode) -> int:
        self.best = 0

        def arrow(node: TreeNode) -> int:
            if not node:
                return 0
            l = arrow(node.left)
            r = arrow(node.right)

            left  = l + 1 if node.left  and node.left.val  == node.val else 0
            right = r + 1 if node.right and node.right.val == node.val else 0

            self.best = max(self.best, left + right)
            return max(left, right)

        arrow(root)
        return self.best

The extra constraint appears only in deciding whether an arm is valid: a child with a different value breaks that arm, so its contribution becomes zero, which replaces the clipping.

Two more shapes

If the quantity becomes a product, clipping is dangerous, because two negatives multiply positive and a negative arm can help. That forces two return values, the maximum and the minimum:

def gain(node):
    if not node:
        return (1, 1)
    lmax, lmin = gain(node.left)
    rmax, rmin = gain(node.right)
    cands = [node.val, node.val * lmax, node.val * lmin,
             node.val * rmax, node.val * rmin]
    self.best = max(self.best, max(a * b for a in cands for b in cands))
    return (max(cands), min(cands))

The lesson is that the zero is the lower bound appropriate to addition, and changing the operation requires re-deriving the bound rather than copying the template.

For the deepest leaves, the pair becomes height and answer:

def dfs(node):
    if not node:
        return (0, None)
    ld, llca = dfs(node.left)
    rd, rlca = dfs(node.right)
    if ld == rd:
        return (ld + 1, node)
    if ld > rd:
        return (ld + 1, llca)
    return (rd + 1, rlca)

Equal depths mean this node is the peak, and unequal means carry only the deeper side, which is structurally identical to the two quantities here.

Java

class Solution {
    private int best = Integer.MIN_VALUE;

    public int maxPathSum(TreeNode root) {
        gain(root);
        return best;
    }

    private int gain(TreeNode node) {
        if (node == null) return 0;
        int left  = Math.max(gain(node.left),  0);
        int right = Math.max(gain(node.right), 0);

        best = Math.max(best, node.val + left + right);

        return node.val + Math.max(left, right);
    }
}

One caveat: the minimum integer can overflow in extreme cases. The constraints here make it safe, and mentioning that is worth a note.

The three most commonly wrong cases: a single negative node, which exposes a zero initial value; an all-negative tree, which exposes both the initial value and the one-node rule; and a root with a negative child, which exposes missing clipping.

Common mistakes

  1. Returning the full two-arm sum. The sample still passes because the root is negative and the inflated value is never selected, so it fails only on other trees. Check with a symmetric tree of one, two, three: the correct report from the root is four, the wrong one is six.
  2. Starting the best at zero, which fails on all-negative trees.
  3. Treating the clipping as a null guard. Without it, the one-minus-two-plus-three case returns two instead of four.
  4. Updating the answer after returning, so the peak candidate is never recorded.
  5. Returning negative infinity from an empty subtree instead of zero. An empty subtree neither helps nor hurts, and zero means exactly "do not come this way".

How to answer it

First define the two quantities, since that is the scoring point: the peak path at this node, using both arms, which only updates the global answer, and the contribution reported upward, which takes one arm.

Then explain why one arm: the parent will bend again, and if both arms were spent here the parent bend would produce a fork, which is not a path.

Then the semantics of clipping: not a null check, but a decision that a negative arm only lowers the sum, so zero means do not come this way.

Then the initial value: negative infinity, because a path holds at least one node and values can be negative; zero would answer zero for a single negative node.

Then complexity and the link to the diameter problem, which is the same skeleton with edges instead of values and no clipping.

Asked to avoid a global variable, return a tuple of contribution and best. Asked about stack overflow, agree, since a skewed tree of thirty thousand nodes exceeds Python's default limit, and offer either a raised limit or an explicit stack.

Closing

Ten lines, and they force a realisation that few other problems demand: for a single node, the value reported upward and the value used to update the answer can be different values.

Once that is clear, the clipping is no longer incidental insurance and the initial value is no longer a habit; both are the logic of the problem.

This one-node two-quantities skeleton carries across the diameter, the univalue path, the deepest leaves, and even the product variant. Faced with any longest-path-on-a-tree question, ask two things: what is reported upward, which is one arm, and what updates the answer, which is both.
