Poker straight: jokers fill gaps, never duplicates

2026-10-14 · 12 min · Stack Frame

The problem

Given five cards numbered one to thirteen, decide whether they form a straight. The follow-up adds jokers, written as zero, usable as any card.

[1,2,3,4,5]      -> true
[0,0,1,2,5]      -> true    (the jokers become three and four)

Ten lines of code, and all the marks are in the details: duplicates, what the jokers may and may not do, and the boundary. The official samples are only two, and they happen to let all three common wrong answers through.

Collapse the question into differences

Do not ask whether the five cards are a straight; ask how far apart neighbours are after sorting. In a straight every gap is one, and a joker can fill a gap of any size, one hole per joker.

sort, count jokers, check adjacent gaps,
spend jokers on the holes, succeed if the budget covers them

One constraint hides in the statement and is the one most often missed: a straight consists of five distinct numbers. A joker can supply a missing number and cannot remove a duplicate. Two twos stay two twos no matter how many jokers are in hand.

So: no duplicates plus a small enough span means a straight, and the jokers merely loosen the span by their count.

Without jokers, five distinct cards form a straight exactly when every adjacent gap is one, equivalently when the maximum minus the minimum is four. Note that it is exactly four, not at most: a span of five looks almost right and is genuinely missing one card in the middle.

With jokers

def is_straight(cards: list[int]) -> bool:
    if len(cards) != 5:
        raise ValueError("exactly five cards")
    s = sorted(cards)
    jokers = s.count(0)
    rest = s[jokers:]
    for i in range(1, len(rest)):
        if rest[i] == rest[i - 1]:
            return False
        if rest[i] - rest[i - 1] > 1:
            jokers -= rest[i] - rest[i - 1] - 1
            if jokers < 0:
                return False
    return True

Three steps: sort so the jokers float to the front, count them as the budget, and spend the budget on holes. The duplicate test comes before spending, because the two failure reasons are independent and neither can rescue the other.

There is a cleaner equivalent criterion, one line long: with the non-jokers distinct, their span must be under five.

def is_straight(cards: list[int]) -> bool:
    s = sorted(cards)
    rest = [c for c in s if c != 0]
    if len(set(rest)) != len(rest):
        return False
    return True if not rest else max(rest) - min(rest) < 5

Why the threshold works: with m non-jokers the number of holes is the span minus m minus one, and having enough jokers reduces exactly to a span of at most four. With no jokers it tightens automatically to exactly four, since five distinct numbers span at least four. One criterion covers both versions.

Java

public class PokerStraight {
    public static boolean isStraight(int[] cards) {
        if (cards == null || cards.length != 5) {
            throw new IllegalArgumentException("exactly five cards");
        }
        Arrays.sort(cards);
        int jokers = 0;
        while (jokers < 5 && cards[jokers] == 0) {
            jokers++;
        }
        for (int i = jokers + 1; i < 5; i++) {
            if (cards[i] == cards[i - 1]) {
                return false;
            }
            jokers -= cards[i] - cards[i - 1] - 1;
            if (jokers < 0) {
                return false;
            }
        }
        return true;
    }
}

There is no overflow risk here, so the traps are all in initialisation. Initialising the minimum to zero makes the span one too large and rejects a genuine straight; including the jokers when computing the span makes it larger still, and rejects the second sample. Both share one lesson: a joker is not a card with the value zero, it is a card whose value is undecided, so it plays no part in span or duplicate checks and appears only when filling holes.

Variants

With a wraparound ace, where ten through ace also counts, test both identities: if an ace is present, substitute fourteen and test again, accepting if either reading works. Hands like ace, ten, eleven, twelve, thirteen succeed under the second reading; thirteen, ace, two, three, four fail under both.

More than two jokers changes nothing in the algorithm, since the count is just a number. A real deck holds two, so more than that is invalid input and a defensive check is worth mentioning.

Choosing five cards from a larger hand turns the decision into a search: look for a window of five consecutive ranks containing at least five distinct cards plus jokers.

A flush adds a suit dimension: group by suit first, then apply the same test inside the group.

Complexity

Constant time and space, since a five-card sort is bounded. The interesting axis is correctness rather than efficiency. As a sanity check on the criterion, exhaustive enumeration confirms the counts: nine straights out of twelve hundred eighty-seven jokerless combinations, thirty-seven of seven hundred fifteen with one joker, and fifty-eight of two hundred eighty-six with two, so jokers make straights roughly thirty times more likely than without.

Three bugs the official samples miss

Checking only the span and not duplicates lets a hand with two twos through, since its span is small. Writing the span test as at most five instead of strictly under five lets through a hand missing a middle card with no joker. And iterating the gaps from index one, over the jokers as well, subtracts one per adjacent joker pair, which cancels a real hole: a hand with two jokers and three genuine holes passes the ledger while being impossible.

Keep those three counterexamples on hand. Note also the two mistakes from the Java section, which fail in the opposite direction by rejecting valid hands, and which the official samples do catch. Sample coverage is biased, so it cannot be the only test.

How to answer it

The short version: sort with jokers first, count the budget, compare adjacent gaps, spend one joker per missing card, reject duplicates outright, and fail when the budget runs out. Constant time and space. If there is time, add the equivalent one-line criterion, the three counterexamples, and the variant notes about the ace and about invalid inputs.
